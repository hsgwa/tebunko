    画面のテストと確認¶

    扱うこと: 画面が使う関数・画面の型と判断層・画面の部品の単体テストが何を確かめるか、画面の確認（自動化できた範囲・手動で確かめる範囲）。扱わないこと: 画面以外の単体テスト（単体テスト（インデックスと検索） など）、本物の画面を UI オートメーションで操作するスモークテストの仕組み・場面（画面のスモークテスト）。先に読むページ: テスト。

    判断層（*_view.ps1）はそのままテストする。result_list.ps1・open_source.ps1・preview.ps1・index_tree.ps1 は $ui・$window を偽物にし、Excel・エクスプローラーの起動は Mock して実際には開かない。クリップボードは利用者の PC のものを書き換えるため、「コピーしない場合」（preview.ps1 の copyPreviewSelection）だけを確かめる。型（shared/ui/types.ps1・tebunko/ui/types.ps1）はプロパティの変更通知と各メソッドを確かめる。

    画面の単体テスト¶

    画面が使う関数と画面の部品を Pester 5.9.0 で確かめる（実行方法・タグ・カバレッジは テストの実行と CI）。画面の部品（ui/*.ps1）のテストは、WPF のコントロール（$ui.ResultGrid など）を偽のオブジェクトに差し替え、読み込み時に登録されたイベントの処理を直接呼んで確かめる。画面を開かないため、CI でも動く。

    画面が使う tebunko/lib.ps1 の関数（画面の実装構成）
