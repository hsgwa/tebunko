# インデックスとは

tebunko を使うときに、いちばん大事な言葉が**インデックス**です。このページでは、インデックスが何か、なぜ要るのか、いつ作り直せばよいのかを説明します。

## ひとことで言うと

インデックスは、**検索のために前もって作っておく「文字の控え」**です。tebunko は、Excel・Word・PowerPoint のファイルの中の文字を先に書き写しておき、検索するときは、その控えだけを見ます。

## 本の「索引」と同じしくみ

分厚い本で「請求書」という言葉が出てくるページを探すとき、1 ページ目から全部読むと時間がかかります。巻末の**索引**を見れば、「請求書 …… 12、48、103 ページ」とすぐに分かります。

tebunko のインデックスも同じです。

| | インデックスが無いと | インデックスがあると |
|---|---|---|
| 探し方 | 検索のたびに、ファイルを 1 つずつ開いて中を読む | 書き写しておいた文字の控えの中から探す |
| かかる時間 | ファイルが 1,000 個あれば、1,000 回ファイルを開く | 数秒（100 万行の控えでも 1〜2 秒） |
| 分かること | — | どのファイルの、どのシート・ページ・スライドの、何行目か |

そのかわり、**索引は前もって作っておく必要があります**。これが［1 インデックス管理］の［インデックス作成を開始］です。

## 使うときの流れ

```mermaid
flowchart LR
    F["元のファイル<br>（Excel・Word・PowerPoint）"] -- "① インデックス作成<br>文字を書き写す" --> I[("インデックス<br>（文字の控え）")]
    I -- "② 検索<br>控えの中から探す" --> R["検索結果<br>ファイル名・シート・行"]
    R -- "③ ダブルクリック" --> F
```

1. **インデックスを作る**：登録したフォルダの中のファイルを開いて、文字を書き写します。最初は時間がかかります（300 ファイルで 3 分ほど）。
2. **検索する**：書き写した控えの中から探すので、すぐに結果が出ます。
3. **元のファイルを開く**：結果をダブルクリックすると、控えではなく**元のファイル**が開きます。

## よくある疑問

### いつ作り直せばいいの？

**ファイルを追加したり、書き換えたりしたあと**です。インデックスは「作ったときの控え」なので、そのあとに変わった中身は、作り直すまで検索に出てきません。

作り直しといっても、2 回目からは**新しいファイルと変わったファイルだけ**を書き写すので、すぐに終わります（変更が無ければ数秒）。週の初めや、探す前に［インデックス作成を開始］を押す、くらいで十分です。

### 元のファイルは書き換わらない？

書き換わりません。tebunko は元のファイルのコピーを読み取り専用で開いて、文字を書き写すだけです。

### インデックスはどこにあるの？

ワークスペースというフォルダ（既定は `ドキュメント\tebunko_ws`）の中の `index` にあります。元のファイルとは別の場所です。インデックスを消しても、元のファイルは消えません（もう一度作れば元に戻ります）。

### 画面の「インデックス」は、登録したフォルダのこと？

はい。tebunko では、**登録したフォルダ 1 つごとに 1 つのインデックス**を作ります。［1 インデックス管理］の一覧に並んでいる 1 行 1 行が、それぞれのインデックスです。インデックス名はフォルダ名から自動で付き、検索結果にも出ます。

| 登録したフォルダ | インデックス名（例） |
|---|---|
| `C:\共有\営業部` | 営業部 |
| `\\server\総務\規程集` | 規程集 |

### インデックスに気をつけることは？

インデックスには、**文書の文字がそのまま入っています**。元のフォルダに「この人しか見られない」といったアクセス権が付いていても、インデックスには引き継がれません。ワークスペースは、自分だけが使えるフォルダにしておいてください（[設定](settings.md#ワークスペース)）。

### Windows の「インデックスのオプション」とは違うもの？

別のものです。Windows にも、ファイルを探しやすくするための索引（Windows Search）があります。tebunko のインデックスは tebunko が自分で作るもので、Windows Search が無くても使えます。ただし、インデックスが大きいときは、Windows Search も使ってさらに速く探します（[高速検索](fast-search.md)）。
