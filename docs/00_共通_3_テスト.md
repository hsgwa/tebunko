| パスワード付きの `.docx` / `.doc` / `.pptx` | ダイアログを出さずに失敗として記録される | 変換 |
| テンプレート `.dotx`、`~$` で始まる `.docx` | 変換対象にならない | 変換 |
| 変換後の Word・PowerPoint プロセス | 残らない（利用者が使用中の Word には触れない） | 変換 |

### 6.3 テストの構成と実行

テストは `scripts/` と同じ構成に並べる。どのモジュールのテストがどこにあるか、たどらなくても分かるようにするため。

| フォルダ | 内容 |
|---|---|
| `tests/helpers/` | 共通の準備（`load.ps1`。`$here`・`${scriptsDir}` を決めて `tebunko_grep/lib.ps1` を読み込む）とテスト用の TSV 作成（`tsv.ps1`） |
| `tests/shared/core/` | `fs`・`text`・`folder`・`settings` |
| `tests/shared/office/` | `office_files`・`office_process`・`office_reader`・`office_app` |
| `tests/tebunko_grep/core/` | `settings`（`setting.config`） |
| `tests/tebunko_grep/index/` | `index_name`・`index_store` |
| `tests/tebunko_grep/convert/` | `convert_state`・`convert_decide`・`convert_plan`・`convert_office` |
| `tests/tebunko_grep/search/` | `search_query`・`search_run`・`source_map` |
| `tests/tebunko_grep/ui/` | 画面の判断層（`index_view`・`convert_view`・`search_view`・`preview_view`） |
| `tests/meta/` | 構成を守るテスト（`structure`・`encoding`・`layers`）と安全性の検査（`safety`） |
| `tests/testdata/` | 手動の結合テスト用のデータ（6.2）と、その生成・個人情報の除去（`scrub_personal`） |

`tests/meta/` は、直し忘れると気づきにくい決まりごとを機械的に確かめる。

| テスト | 確かめること |
|---|---|
| `structure` | `$rootDir` などのパス定義、全 `.ps1` の構文、`Add-Type -TypeDefinition` を使わない、XAML が XML として読める・`x:Name` がある、型を読み込む順で継承が解決できる |
| `encoding` | 全 `.ps1`・`.xaml` が BOM 付き UTF-8 で、改行が CRLF |
| `layers` | `shared/` にツールの名前が出てこない、ツール同士が互いを読み込まない、起動口からたどれない `.ps1` が無い、判断層に画面への依存が無い |
| `safety` | 危険な処理を使っていない、Office をマクロ無効・読み取り専用で開く、原本を書き換えない、書き込み先が `work`・`%TEMP%` だけ、PSScriptAnalyzer の指摘が 0 件、審査用の資料がそろっている（[04_安全性.md](04_安全性.md)） |

#### タグと実行

`Describe` にタグを付け、実行するものを選べるようにする。

| タグ | 内容 | 外部ソフト |
|---|---|---|
| `Unit` | 判断層（入力は素の値、出力は素の値） | 不要 |
| `Io` | ファイルの読み書き（`$TestDrive` の中で完結する） | 不要 |
| `Meta` | 構成を守るテスト | 不要 |
| `Office` | Excel・Word・PowerPoint の COM を実際に動かすもの | 必要 |
| `Slow` | 時間のかかるもの | 不要 |

実行は `tests/run.ps1` から行う。

```
.\tests\run.ps1              既定（Unit・Io・Meta。Office と Slow は外す）
.\tests\run.ps1 -Tag Unit    速い確認だけ
.\tests\run.ps1 -All         Office・Slow も含める（Office が必要）
.\tests\run.ps1 -Ci          結果の XML（work\test\results.xml）とカバレッジを出す
```

いずれも失敗したテストの数を終了コードにする（pre-commit フックと CI が見る）。

カバレッジは判断層・状態層だけを対象にする（画面層 `gui.ps1`・`*_tab.ps1`・`shell.ps1`・`app_host.ps1`・`*_dialog.ps1` は自動テストの対象外のため）。
下限は `tests/coverage.baseline` に置き、下回ると `-Ci` が失敗する。上がったら基準を上げる。

#### CI

`.github/workflows/test.yml` で、push と pull request のたびに windows ランナーで実行する。

- Windows PowerShell 5.1 はランナーに最初から入っている（`shell: powershell` を明示する。`pwsh`（PowerShell 7）では COM と文字コードの扱いが変わる）
- ランナーには Pester 5 も入っており、そのままでは `Invoke-Pester` が 5 を読み込んで全テストが失敗する（5 はテストの書き方が違う）。`tests/run.ps1` は `Import-Module Pester -MaximumVersion 3.99.99` で 3 系を明示し、CI は 3 系が無ければ 3.4.0 を入れる
- スクリプトの改行はランナーの `core.autocrlf` に左右されないよう、`.gitattributes` で `.ps1`・`.xaml`・`.bat` を CRLF に固定している
- ランナーに Office は入っていないため、タグ `Office` のテストは自動的に外れる。COM を使う変換の確認は手元で `-All` を使う（6.2）
- あわせて PSScriptAnalyzer の `Error` を 0 件に保つ（継承元が別ファイルのための `TypeNotFound` は除く）。安全性の検査（`tests/meta/safety.Tests.ps1`）はタグ `Meta` のため既定で実行され、PSScriptAnalyzer が入っていない環境では静的解析の項目だけを飛ばす
- テストの前に `tools/check_commit.ps1` で、追跡している全ファイルと全コミットの作者を検査する（下の「公開してはいけない内容の検査」）。作者を全履歴で調べるため `fetch-depth: 0` で取得する
- 同じブランチに続けて push したときは、古い実行を取り消す（`concurrency`）

`v` で始まるタグを push すると `.github/workflows/release.yml` が動き、`test.yml` と同じ検査・テストを通したうえで、`tools/new_release_package.ps1` で配布 zip（`tebunko_grep-<タグ>.zip`）を作って GitHub Release に載せる。zip にはカタログ（`tebunko.cat`）とハッシュ一覧（`SHA256SUMS.txt`）を同梱し（[04_安全性.md](04_安全性.md) の 5.1）、zip 自体の SHA256 をリリースの説明に書く（同 5.6 の VirusTotal での照会用）。

```
git tag v1.0.0
git push origin v1.0.0
```

#### コミット前の検査（pre-commit フック）

clone したら 1 回だけ次を実行する。`core.hooksPath` を `tools/hooks` にし、コミットのたびに `tools/hooks/pre-commit` が動く（git worktree で作ったツリーでも、そのツリーのフックが動く）。

```
.\tools\install_hooks.ps1              有効にする
.\tools\install_hooks.ps1 -Uninstall   やめる
```

| 順 | 内容 | 所要時間の目安 |
|---|---|---|
| 1 | `tools/check_commit.ps1 -Staged`：ステージした内容と、これから作るコミットの作者を検査する | 数秒 |
| 2 | `tests/run.ps1 -Tag Unit,Meta -Quiet`：速いテスト（`Io` を含む既定のテストと静的解析は CI で行う）。失敗したテストだけを表示する | 5 秒程度 |

どうしても飛ばすときは `git commit --no-verify`。CI で同じ検査が走る。フックは git for Windows の sh が読むため LF で保存する（`.gitattributes` で固定）。

#### 公開してはいけない内容の検査（`tools/check_commit.ps1`）

リポジトリは公開しているため、履歴に一度でも入れたら公開されたのと同じになる（CLAUDE.md「個人情報を書かない」）。これを機械的に止める。

| 対象 | 見つけたら失敗にするもの | 例示用として通すもの |
|---|---|---|
| 絶対パス | `C:\Users\<名前>`（`/` 区切り・`\\` のエスケープも） | `test`（`test_` のように長さを揃えたものも）・`a`・`Public`・`%USERNAME%` `<利用者名>` のような置き換え用の表記 |
| メールアドレス | すべて | `example.com` などの例示用のドメイン、GitHub の noreply |
| Office ファイル | 作成者・最終更新者（`docProps/core.xml`・ODF の `meta.xml`・PDF の `/Author`）、コメント・変更履歴の作成者に付くアカウント ID（`userId`） | `test`、空、`0` だけの ID |
| 手元で実行したとき | Windows のユーザー名そのもの（CI では調べない） | — |
| `.ps1`・`.xaml` | BOM 付き UTF-8 でない、改行が CRLF でない | — |
| コミットの作者・コミッター | GitHub の noreply 以外のメールアドレス | `noreply@github.com`（GitHub 上でマージしたときのコミッター） |

Office ファイル（ZIP）は展開して中の XML・バイナリを 1 つずつ調べる。旧形式（`.doc` `.xls` `.ppt`）・PDF などはバイト列を UTF-8 と UTF-16LE の両方で読んで調べる。中身は作業ツリーではなく git に記録される内容を読む（改行だけは、git が LF にして記録するため作業ツリーのファイルで調べる）。
