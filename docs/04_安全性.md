# win_grep 安全性説明書

本書は、本ツールの導入を審査する担当者（情報システム部門・セキュリティ部門など）に向けて、**本ツールが何をするか・何をしないか**と、**その根拠をどう自分の手で確認できるか**を示すものである。

本書の主張はすべて `scripts/*.ps1` の実装に基づく。各項目には**確認コマンド**を併記しているため、審査する側が本書を信用せずに、自分で同じ結果を再現できる。機械での検査は `tests/safety.Tests.ps1` にまとめてあり、`Invoke-Pester .\tests\safety.Tests.ps1` で一括実行できる。

関連文書: 全体構成と動作環境は [00_index.md](00_index.md)、フォルダ構成は [00_共通_1_フォルダ構成と設定ファイル.md](00_共通_1_フォルダ構成と設定ファイル.md)、プロセス停止機能は [03_画面_3_プロセス停止タブ.md](03_画面_3_プロセス停止タブ.md) を参照。

## 1. 要約

| 観点 | 本ツールの挙動 |

| 構成物 | Windows PowerShell スクリプト（`scripts/*.ps1`）と画面定義（`*.xaml`）、起動用 `win_grep.bat`、アイコン `win_grep.ico` のみ。実行可能バイナリ（`.exe` / `.dll`）を同梱しない |

実行時コンパイル（`csc.exe` の起動）は、本ツールでは**意図的に排除した**経緯がある。検索処理・パス解決・画面の型定義は、いずれも当初 C# を `Add-Type` でコンパイルしていたものを PowerShell の実装に置き換えている（`common.ps1:2172`、`common.ps1:757`、`config_gui.ps1:63` 等のコメントに記録）。これにより、実行時に一時フォルダへコンパイル結果を書き出す動作が無くなり、EDR やアプリケーション制御（AppLocker・WDAC）との衝突も避けられる。

### 2.2 Office ファイルを開くときの設定

変換のために Excel・Word・PowerPoint を COM で操作するが、開くときに次の設定を行う（`office_to_tsv.ps1:310-331`）。

| 設定 | 値 | 意味 |
|---|---|---|
| `AutomationSecurity` | `3`（`msoAutomationSecurityForceDisable`） | **マクロを強制的に無効にする**。マクロ有効ファイル（`.xlsm` / `.docm` / `.pptm`）でもマクロは実行されない |
| `EnableEvents` | `$false` | `Workbook_Open` などのイベントマクロを発火させない |
| `AskToUpdateLinks` | `$false`、`Workbooks.Open` の `UpdateLinks` = `0` | **外部リンクを更新しない**。他ブックや外部データソースへのアクセスが発生しない |
| `Visible` | `$false` | 画面に出さずに処理する（変換中に利用者の操作を妨げない） |
| `DisplayAlerts` | 無効 | ダイアログで処理が止まらないようにする |
| `Workbooks.Open` の `ReadOnly` | `$true` | 読み取り専用で開く（Word・PowerPoint も同様に読み取り専用で開く） |

パスワード付きファイルは、開くときに固定文字列 `"dummy"` をパスワードとして渡す（`office_to_tsv.ps1:564`・`648`・`669`）。これはパスワードを破るための処理ではなく、**パスワード入力ダイアログを出さずに確実に失敗させる**ための指定である。結果としてパスワード付きファイルは変換されず、`work\変換一覧.tsv` に失敗として記録される。本ツールがパスワードを入力・保存・送信することはない。

### 2.3 外部プロセスの起動（4 か所）

| 場所 | 起動するもの | 用途 |
|---|---|---|
| `config_gui.ps1:2317`・`2322`・`3645` | `explorer.exe` | 検索結果から元のファイルの場所を開く（利用者の操作時のみ） |
| `config_gui.ps1:2603` | `powershell.exe` | 本ツール自身の変換処理 `office_to_tsv.ps1` を起動（`-WindowStyle Hidden`、`-ExecutionPolicy RemoteSigned`） |

## 3. ファイルの読み書きの範囲

### 3.1 書き込み・削除する場所

書き込みは次の場所に限られる。

| 場所 | 内容 | 定義 |
|---|---|---|
| `work/` 配下（ツールを置いたフォルダの直下） | TSV インデックス（`work/index/`）、変換一覧・変換ログ・制御用ファイル、検索結果 | `common.ps1:4-6`・`11` |
| `%TEMP%\win_grep\<PID>` 配下 | 変換中の作業領域（原本のコピー・中間 TSV）。変換の完了時・開始時に空にする | `common.ps1:9` |
| `setting.config`（ツールを置いたフォルダの直下） | 画面が保存する設定（変換対象フォルダ・検索対象インデックスなど） | `common.ps1:143-150` |
| 利用者が指定した出力先 | ［結果をファイルに出力］の保存先（既定は `work\検索結果.txt`） | 画面のダイアログで利用者が指定 |

削除処理は 18 か所あるが、対象はすべて上記のうち `work/` 配下または `%TEMP%\win_grep\<PID>` 配下、すなわち**本ツールが自分で作ったファイル**である。変換対象フォルダ内のファイルを削除する処理は無い。

確認コマンド（`scripts` フォルダで実行）:

```powershell
# 削除・書き込みの呼び出し箇所をすべて列挙し、対象のパスが work / tmpDir 由来であることを確認する
Select-String -Path *.ps1 -Pattern 'Remove-Item','WriteAllText','WriteAllLines','StreamWriter','\.SaveAs'
```

### 3.2 変換対象のファイルは書き換えない

本ツールは、変換対象フォルダのファイルを**開かない**。作業フォルダへコピーし、そのコピーだけを開く（`office_to_tsv.ps1:548-557`・`689-693` の `copyFileShared`）。この設計は元々、変換中に利用者が原本を上書き保存・移動できるようにするため（ファイルロックを避けるため）に入れたものだが、結果として原本への書き込み経路そのものが存在しない状態になっている。

```mermaid
flowchart LR
    src[("変換対象フォルダ<br>原本")]
    copy["%TEMP%\win_grep\#lt;PID#gt;<br>コピー"]
    office["Excel / Word / PowerPoint<br>読み取り専用・マクロ無効"]
    tsv["%TEMP%\win_grep\#lt;PID#gt;<br>中間 TSV"]
    idx[("work/index/<br>TSV インデックス")]

    src -- "コピー（読み取りのみ）" --> copy
    copy --> office
    office -- "SaveAs（保存先はコピー側）" --> tsv
    tsv --> idx
```

Office の `SaveAs` は 3 か所あるが、保存先は常に作業フォルダ内のパス（`$tmpPath` / `$destPath`）である（`office_to_tsv.ps1:598`・`649`・`673`）。原本のパスを `SaveAs` に渡す経路は無い。

### 3.3 読み取りのみであることの実証

静的な確認に加えて、実際に動かして確認できる。第三者が再現できる手順は次の 2 つ。

**手順 A: ハッシュの比較**

```powershell
$target = "C:\確認用\対象フォルダ"
$before = Get-ChildItem $target -Recurse -File | Get-FileHash
# ここで win_grep.bat を起動し、$target を対象にインデックスを作成する
$after  = Get-ChildItem $target -Recurse -File | Get-FileHash
Compare-Object $before $after -Property Path,Hash   # 何も出力されなければ、原本は 1 バイトも変わっていない
```

**手順 B: 書き込み権限を外して実行**

対象フォルダに読み取り専用の権限だけを与えたアカウントで、インデックス作成を最後まで実行する。書き込みを試みていれば必ず失敗するため、完走することが「読み取りのみ」の裏付けになる。

**通信しないことの実証**

インデックス作成中に、対象プロセスの通信状況を記録する。

```powershell
Get-NetTCPConnection -OwningProcess (Get-Process powershell).Id -ErrorAction SilentlyContinue
```

## 4. 開示事項

次の 2 点は、審査で必ず論点になるため、本ツールの側から先に開示する。いずれも隠れた動作ではなく、利用者の明示的な操作に紐づく。

### 4.1 Office プロセスの強制終了（［9 プロセス停止］タブ）

変換が異常終了すると、画面の無い Excel・Word・PowerPoint のプロセスが残り、メモリを占有し続けることがある。これを止めるために、画面の［9 プロセス停止］タブから `Stop-Process -Force` を実行する（`common.ps1:2871`）。

- **影響**: 強制終了するため、対象プロセスで**未保存の内容は失われる**。
- **制御**: 実行されるのは利用者が一覧でチェックした PID のみである（`stopOfficeProcesses` は PID の配列を受け取る）。自動では実行されない。監視・常駐もしない。
- **判断材料の提示**: 一覧には、ウィンドウを持たないプロセス（変換が残したものと判断できる）を区別して表示する（`getOfficeProcesses` の `Background` 列）。利用者が自分で開いている Excel を誤って選ばないようにするための表示である。
- **対象の限定**: 対象は Excel（`EXCEL`）・Word（`WINWORD`）・PowerPoint（`POWERPNT`）のみ（`officeProcessNames`）。他のプロセスは一覧に出ないため、選ぶことができない。

詳細は [03_画面_3_プロセス停止タブ.md](03_画面_3_プロセス停止タブ.md) を参照。

### 4.2 Mark-of-the-Web の解除（`win_grep.bat`）

`win_grep.bat` は、画面を起動する前に配布フォルダ配下の Mark-of-the-Web を解除する。

```bat
powershell -NoProfile -Command "Get-ChildItem -LiteralPath '%~dp0' -Recurse -File | Unblock-File"
```

- **理由**: zip で配布したものを展開すると全ファイルに Mark-of-the-Web が付き、実行ポリシー `RemoteSigned` では未署名スクリプトが実行できないため。
- **範囲**: `%~dp0`（`win_grep.bat` があるフォルダ）配下のみ。システム全体やユーザーのドキュメントには影響しない。
- **実行ポリシー**: `Bypass` は使わず `RemoteSigned` で起動する。恒久的な設定変更（`Set-ExecutionPolicy`）も行わない。
- **恒久的な解消策**: スクリプトにコードサイニング証明書で署名すれば、この `Unblock-File` は不要になり、`AllSigned` でも動作する。署名により配布物の改ざん検知も可能になる。導入審査でこの行が問題になる場合は、署名の導入を検討する。

### 4.3 変換中に Excel が前面に出る場合

検索結果から元の Excel ファイルを開く際、Excel を可視化して前面に出す（`config_gui.ps1:3497`・`3548`）。これは利用者が開くよう操作したときの動作である。変換処理側の Excel は常に不可視（`Visible = $false`）で動作する。

## 5. 第三者のツールによる検査結果

本ツールの作者以外が作ったツールで検査した結果を示す。5.1 と 5.2 は誰でも同じコマンドで再現できる。

### 5.1 静的解析: PSScriptAnalyzer（Microsoft）

PowerShell スクリプトの静的解析ツール。Microsoft が公開しているルールで、コードインジェクション・平文パスワードなどを検出する。

```powershell
Install-Module PSScriptAnalyzer -Scope CurrentUser        # 未導入の場合

# 安全性にかかわるルールでの検査（0 件であることを確認する）
Invoke-ScriptAnalyzer -Path .\scripts -Recurse -Settings .\tests\PSScriptAnalyzer.security.psd1

# 全ルールでの検査（書き方のルールを含む）
Invoke-ScriptAnalyzer -Path .\scripts -Recurse
```

実施結果（PSScriptAnalyzer 1.25.0）:

| 検査 | 結果 |
|---|---|
| 安全性にかかわる 14 ルール（`tests/PSScriptAnalyzer.security.psd1`） | **指摘 0 件** |
| 全ルールのうち `Error` 重大度（構文エラー・重大な問題） | **指摘 0 件** |
| 全ルール | 214 件（`Warning` 175 件 / `Information` 39 件。内訳は下表） |

有効にしている安全性のルールは次の 14 件である。設定ファイルからルールを削って「0 件」にする抜け道を防ぐため、この 14 件が設定に含まれていることも `tests/safety.Tests.ps1` で検査している。

| 分類 | ルール |
|---|---|
| 文字列を式として実行しない | `PSAvoidUsingInvokeExpression` |
| パスワード・資格情報の平文の扱い | `PSAvoidUsingPlainTextForPassword`・`PSAvoidUsingConvertToSecureStringWithPlainText`・`PSUsePSCredentialType`・`PSAvoidUsingUsernameAndPasswordParams` |
| 通信先の固定・暗号化されない通信 | `PSAvoidUsingComputerNameHardcoded`・`PSAvoidUsingAllowUnencryptedAuthentication` |
| 危険・非推奨な API | `PSAvoidUsingBrokenHashAlgorithms`・`PSAvoidUsingWMICmdlet` |
| 標準コマンドの上書き・別名の定義 | `PSAvoidOverwritingBuiltInCmdlets`・`PSAvoidGlobalAliases`・`PSReservedCmdletChar`・`PSReservedParams` |
| 文字コード | `PSUseBOMForUnicodeEncodedFile` |

全ルールで出る 214 件の内訳は次のとおりで、**すべて書き方（可読性・保守性）のルール**である。安全性の判断には関わらない。

| 件数 | ルール | 内容と本ツールでの理由 |
|---|---|---|
| 58 | `PSAvoidUsingWriteHost` | `Write-Host` で画面・ログへ出力している。変換処理の進み具合と失敗の原因を利用者に見せるための出力であり、パイプラインへ返す値ではない |
| 42 | `PSReviewUnusedParameter` | 画面のイベントハンドラーの引数（`sender`・`e`）など、WPF の呼び出し規約で受け取るだけの引数 |
| 39 | `PSAvoidUsingPositionalParameters` | COM の呼び出し（`Workbooks.Open` 等）は引数の順序が API 側で決まっており、名前付きにできない |
| 34 | `PSAvoidUsingEmptyCatchBlock` | 権限の無いプロセスの起動時刻が取れない場合など、失敗しても処理を続けるべき箇所。理由は各 `catch` にコメントで記載している |
| 25 | `PSAvoidAssignmentToAutomaticVariable` | WPF のイベントハンドラーの引数名 `sender` に対する指摘。PowerShell の自動変数と同名だが、ハンドラー内の引数であり影響しない |
| 16 | `PSUseDeclaredVarsMoreThanAssignments` | `-ErrorVariable` で受け取る変数など、別の構文で使う変数 |

なお `tests/testdata/make_testdata.ps1` には `PSAvoidUsingPlainTextForPassword` の指摘が 7 件出る。パスワード付きの Office ファイルを**テストデータとして作る**スクリプトであり、パスワードは固定のテスト用文字列である。利用者へ配布する `scripts/` には含まれない。

### 5.3 複数エンジンでの検査: VirusTotal（外部へファイルを送信する）

約 70 社のエンジンで一度に判定でき、結果が URL として残る。ただし**アップロードしたファイルはセキュリティ各社と共有される**ため、社外に出せないコードを含む場合は実施しない。その場合は次のいずれかで代える。

- 5.2 のローカルスキャン（送信なし）で代える。
- ファイルのハッシュだけを照会する（ハッシュは内容を復元できない。ただし過去に誰かが同じファイルを提出していない限り「未登録」となる）。

```powershell
Get-FileHash .\win_grep.zip -Algorithm SHA256    # この値を VirusTotal の検索欄で照会する
```

### 5.4 動作による確認

3.3 の手順 A・B（原本のハッシュ比較、読み取り専用権限での実行）と、通信状況の記録を行う。ツールの実装ではなく**実際の動作**を根拠にできるため、静的な検査より強い証拠になる。

### 5.5 同梱の機械検査

上記の結果と、2 章・3 章の主張を、1 つのコマンドで検査できる。

```powershell
Invoke-Pester .\tests\safety.Tests.ps1
```

`tests/safety.Tests.ps1` は次を検査する（26 件）。将来の変更でいずれかの前提が崩れれば失敗する。

- 2 章の禁止する処理が 0 件であること、許す処理（`Add-Type`・`Start-Process`・`Stop-Process`）が限定されていること
- Office をマクロ無効・イベント無効・外部リンク更新なし・読み取り専用で開くこと
- 原本のパスを書き込み・削除の API に渡さないこと、`SaveAs` の保存先が作業フォルダだけであること
- 書き込み先が `work` 配下と `%TEMP%` 配下に限られること
- PSScriptAnalyzer の安全性ルールの指摘が 0 件、`Error` 重大度が 0 件であること（未導入の環境では自動的に飛ばす）

### 5.7 さらに第三者性を上げる場合

本書の検査は、いずれも「本ツールの作者以外が作ったツール」による検査である。**人による第三者のレビュー**が必要な場合は次の選択肢がある。

| 手段 | 費用・期間 | 得られるもの |
|---|---|---|
| 導入先のセキュリティ部門によるレビュー | 無料・数日〜数週 | 導入先の基準での承認。本書と 5.1〜5.5 の結果を提出物にできる |
| コードサイニング証明書での署名 | 年 5〜20 万円 | 配布物の発行者と改ざんの検知。4.2 の `Unblock-File` も不要になる |
| セキュリティベンダーのソースコード診断 | 数十万円〜・2〜4 週 | 第三者の診断報告書 |
