# win_grep 安全性説明書

本書は、本ツールの導入を審査する担当者（情報システム部門・セキュリティ部門など）に向けて、**本ツールが何をするか・何をしないか**と、**その根拠をどう自分の手で確認できるか**を示すものである。

本書の主張はすべて `scripts/` 配下の実装に基づく。各項目には**確認コマンド**を併記しているため、審査する側が本書を信用せずに、自分で同じ結果を再現できる。機械での検査は `tests/meta/safety.Tests.ps1` にまとめてあり、`.\tests\run.ps1 -Tag Meta` で一括実行できる。

関連文書: 全体構成と動作環境は [00_index.md](00_index.md)、フォルダ構成は [00_共通_1_フォルダ構成と設定ファイル.md](00_共通_1_フォルダ構成と設定ファイル.md)、プロセス停止機能は [03_画面_3_プロセス停止タブ.md](03_画面_3_プロセス停止タブ.md)、脆弱性の連絡先は [SECURITY.md](../SECURITY.md) を参照。

## 2. 危険とされる処理の検査結果

### 2.1 検査項目と結果

検査対象は `scripts/` 配下のすべての `.ps1`（40 ファイル）である。「該当 0 件」は、下表の確認コマンドが 1 件も出力しないことを意味する。

| # | 危険とされる処理 | 結果 | 確認コマンド（リポジトリ直下で実行） |
|---|---|---|---|
| 1 | 文字列を式として実行（`Invoke-Expression` / `iex` / `[ScriptBlock]::Create`） | 該当 0 件 | `Get-ChildItem .\scripts -Recurse -Filter *.ps1 \| Select-String -Pattern 'Invoke-Expression','[^-\w]iex[ (]','ScriptBlock\]::Create'` |
| 2 | 難読化されたコマンド（Base64・`-EncodedCommand`） | 該当 0 件 | 同上、パターンを `'FromBase64String','EncodedCommand'` にする |

| 4 | Windows API の直接呼び出し（P/Invoke） | 該当 0 件 | 同上、`'DllImport','GetDelegateForFunctionPointer'` |
| 5 | C# ソースの実行時コンパイル | 該当 0 件 | 同上、`'Add-Type'` で出る行がすべて `-AssemblyName` であること |
| 6 | レジストリの読み書き | 該当 0 件 | 同上、`'HKLM','HKCU','Set-ItemProperty','New-ItemProperty','Registry::'` |

| 8 | 実行ポリシーの恒久変更・`Bypass` | 該当 0 件 | 同上 + `Select-String -Path .\win_grep.bat -Pattern 'Bypass','Set-ExecutionPolicy'` |

`Add-Type` は 3 か所あるが、いずれも Windows 標準アセンブリの読み込み（`-AssemblyName`）であり、コードのコンパイルではない。

| 場所 | 読み込むアセンブリ | 用途 |
|---|---|---|
| `win_grep/gui.ps1:8` | `PresentationFramework` / `PresentationCore` / `WindowsBase` / `System.Windows.Forms` | 画面（WPF）の表示 |
| `shared/office/office_reader.ps1:10-11` | `System.IO.Compression` / `System.IO.Compression.FileSystem` | `.docx` / `.pptx`（ZIP）の読み取り |

実行時コンパイル（`csc.exe` の起動）は、本ツールでは**意図的に排除した**経緯がある。検索処理・パス解決・画面の型定義は、いずれも当初 C# を `Add-Type` でコンパイルしていたものを PowerShell の実装に置き換えている（`win_grep/search/search_run.ps1:45` 等のコメントに記録）。これにより、実行時に一時フォルダへコンパイル結果を書き出す動作が無くなり、EDR やアプリケーション制御（AppLocker・WDAC）との衝突も避けられる。この前提は `tests/meta/structure.Tests.ps1` でも検査している。

### 2.2 Office ファイルを開くときの設定

変換のために Excel・Word・PowerPoint を COM で操作するが、開くときに次の設定を行う（`shared/office/office_app.ps1:30-49`）。

| 設定 | 値 | 意味 |
|---|---|---|
| `AutomationSecurity` | `3`（`msoAutomationSecurityForceDisable`） | **マクロを強制的に無効にする**。マクロ有効ファイル（`.xlsm` / `.docm` / `.pptm`）でもマクロは実行されない |
| `EnableEvents` | `$false` | `Workbook_Open` などのイベントマクロを発火させない |
| `AskToUpdateLinks` | `$false`、`Workbooks.Open` の `UpdateLinks` = `0` | **外部リンクを更新しない**。他ブックや外部データソースへのアクセスが発生しない |
| `Visible` | `$false` | 画面に出さずに処理する（変換中に利用者の操作を妨げない） |
| `DisplayAlerts` | 無効 | ダイアログで処理が止まらないようにする |
| `Open` の `ReadOnly` | 真 | 読み取り専用で開く（Excel・Word・PowerPoint いずれも。`win_grep/convert/convert_office.ps1:104`・`181`・`207`） |

パスワード付きファイルは、開くときに固定文字列 `"dummy"` をパスワードとして渡す（`convert_office.ps1:104`・`181`・`207`）。これはパスワードを破るための処理ではなく、**パスワード入力ダイアログを出さずに確実に失敗させる**ための指定である。結果としてパスワード付きファイルは変換されず、`work\変換一覧.tsv` に失敗として記録される。本ツールがパスワードを入力・保存・送信することはない。

### 2.3 外部プロセスの起動（4 か所）

| 場所 | 起動するもの | 用途 |
|---|---|---|
| `win_grep/ui/index_tab.ps1:545`・`550`、`win_grep/ui/open_source.ps1:309` | `explorer.exe` | 検索結果・一覧から元のファイルの場所を開く（利用者の操作時のみ） |
| `win_grep/ui/convert_tab.ps1:196` | `powershell.exe` | 本ツール自身の変換処理 `win_grep/convert.ps1` を起動（`-WindowStyle Hidden`、`-ExecutionPolicy RemoteSigned`） |

元のファイルを開く操作（`win_grep/ui/open_source.ps1:122` 付近）では、`Start-Process` ではなく `ProcessStartInfo` を使う。理由は `[` `]` を含むパスの扱いであり（`Start-Process` は角かっこをワイルドカードとして解釈する）、いずれの場合も起動対象は利用者が選んだ行のファイルと、その関連付けされたアプリケーションである。

## 3. ファイルの読み書きの範囲

### 3.1 書き込み・削除する場所

書き込みは次の場所に限られる。

| 場所 | 内容 | 定義 |
|---|---|---|
| `work/` 配下（ツールを置いたフォルダの直下） | TSV インデックス（`work/index/`）、変換一覧・変換ログ・制御用ファイル、検索結果 | `shared/core/paths.ps1:5`、`win_grep/core/paths_grep.ps1:9`・`14`・`24` |
| `%TEMP%\win_grep\<PID>` 配下 | 変換中の作業領域（原本のコピー・中間 TSV）。変換の完了時・開始時に空にする | `win_grep/core/paths_grep.ps1:8` |
| `setting.config`（ツールを置いたフォルダの直下） | 画面が保存する設定（変換対象フォルダ・検索対象インデックスなど） | `win_grep/core/settings_grep.ps1:4` |
| 利用者が指定した出力先 | ［結果をファイルに出力］の保存先（既定は `work\検索結果.txt`） | 画面のダイアログで利用者が指定 |

削除処理は 18 か所あるが、対象はすべて上記のうち `work/` 配下または `%TEMP%\win_grep\<PID>` 配下、すなわち**本ツールが自分で作ったファイル**である。変換対象フォルダ内のファイルを削除する処理は無い。

確認コマンド（リポジトリ直下で実行）:

```powershell
# 削除・書き込みの呼び出し箇所をすべて列挙し、対象のパスが work / tmpDir 由来であることを確認する
Get-ChildItem .\scripts -Recurse -Filter *.ps1 |
    Select-String -Pattern 'Remove-Item','WriteAllText','WriteAllLines','StreamWriter','\.SaveAs'
```

### 3.2 変換対象のファイルは書き換えない

本ツールは、変換対象フォルダのファイルを**開かない**。作業フォルダへコピーし、そのコピーだけを開く（`win_grep/convert/convert_office.ps1:97`・`235` の `copyFileShared`）。コピー処理自体も読み取り専用で開く（`shared/core/fs.ps1:96`。`FileAccess::Read` で開き、ほかのアプリの読み書き・削除を妨げない）。

この設計は元々、変換中に利用者が原本を上書き保存・移動できるようにするため（ファイルロックを避けるため）に入れたものだが、結果として原本への書き込み経路そのものが存在しない状態になっている。

```mermaid
flowchart LR
    src[("変換対象フォルダ<br>原本")]
    copy["%TEMP%\win_grep\#lt;PID#gt;<br>コピー"]
    office["Excel / Word / PowerPoint<br>読み取り専用・マクロ無効"]
    tsv["%TEMP%\win_grep\#lt;PID#gt;<br>中間 TSV"]
    idx[("work/index/<br>TSV インデックス")]

    src -- "コピー（読み取りのみ）" --> copy
    copy --> office
    office -- "SaveAs（保存先はコピー側）" --> tsv
    tsv --> idx
```

Office の `SaveAs` は 3 か所あるが、保存先は常に作業フォルダ内のパス（`$tmpPath` / `$destPath`）である（`convert_office.ps1:138`・`189`・`213`）。原本のパスを `SaveAs` に渡す経路は無い。

### 3.3 読み取りのみであることの実証

静的な確認に加えて、実際に動かして確認できる。第三者が再現できる手順は次の 2 つ。

**手順 A: ハッシュの比較**

```powershell
$target = "C:\確認用\対象フォルダ"
$before = Get-ChildItem $target -Recurse -File | Get-FileHash
# ここで win_grep.bat を起動し、$target を対象にインデックスを作成する
$after  = Get-ChildItem $target -Recurse -File | Get-FileHash
Compare-Object $before $after -Property Path,Hash   # 何も出力されなければ、原本は 1 バイトも変わっていない
```

**手順 B: 書き込み権限を外して実行**

対象フォルダに読み取り専用の権限だけを与えたアカウントで、インデックス作成を最後まで実行する。書き込みを試みていれば必ず失敗するため、完走することが「読み取りのみ」の裏付けになる。

## 4. 開示事項

次の 5 点は、審査で必ず論点になるため、本ツールの側から先に開示する。4.1・4.2・4.5 は利用者の明示的な操作に紐づく動作、4.3・4.4 はツールの性質上避けられない情報の扱いである。

### 4.1 Office プロセスの強制終了（［9 プロセス停止］タブ）

変換が異常終了すると、画面の無い Excel・Word・PowerPoint のプロセスが残り、メモリを占有し続けることがある。これを止めるために、画面の［9 プロセス停止］タブから `Stop-Process -Force` を実行する（`shared/office/office_process.ps1:43`）。

- **影響**: 強制終了するため、対象プロセスで**未保存の内容は失われる**。
- **制御**: 実行されるのは利用者が一覧でチェックした PID のみである（`stopOfficeProcesses` は PID の配列を受け取る）。自動では実行されない。監視・常駐もしない。
- **判断材料の提示**: 一覧には、ウィンドウを持たないプロセス（変換が残したものと判断できる）を区別して表示する（`getOfficeProcesses` の `Background` 列）。利用者が自分で開いている Excel を誤って選ばないようにするための表示である。
- **対象の限定**: 対象は Excel（`EXCEL`）・Word（`WINWORD`）・PowerPoint（`POWERPNT`）のみ。他のプロセスは一覧に出ないため、選ぶことができない。

詳細は [03_画面_3_プロセス停止タブ.md](03_画面_3_プロセス停止タブ.md) を参照。

### 4.2 Mark-of-the-Web の解除（`win_grep.bat`）

`win_grep.bat` は、画面を起動する前に配布フォルダ配下の Mark-of-the-Web を解除する。

```bat
powershell -NoProfile -Command "Get-ChildItem -LiteralPath '%~dp0' -Recurse -File | Unblock-File"
```

- **理由**: zip で配布したものを展開すると全ファイルに Mark-of-the-Web が付き、実行ポリシー `RemoteSigned` では未署名スクリプトが実行できないため。
- **範囲**: `%~dp0`（`win_grep.bat` があるフォルダ）配下のみ。システム全体やユーザーのドキュメントには影響しない。
- **実行ポリシー**: `Bypass` は使わず `RemoteSigned` で起動する。恒久的な設定変更（`Set-ExecutionPolicy`）も行わない。
- **恒久的な解消策**: 配布物のカタログ（5.1）にコードサイニング証明書で署名すれば、この `Unblock-File` は不要になり、`AllSigned` でも動作する。

### 4.3 インデックスが元文書の本文を保持する（情報の集約）

本ツールは全文検索のために、**元の文書の本文を平文の TSV としてインデックス（`work\index\`）に保持する**。これはツールの目的そのものであり、避けられない。審査では次の点が論点になる。

| 論点 | 内容 |
|---|---|
| アクセス権の非継承 | インデックスは**変換した人の権限で作られる**。元のファイルに設定されたアクセス権は引き継がれない。インデックスを置いた場所を読める人は、元のファイルを読む権限が無くても本文を読める |
| 検索結果ファイル | ［結果をファイルに出力］で書き出す `work\検索結果.txt` にも本文（該当行）が入る |
| 持ち出し経路 | インデックスのフォルダは別の PC へコピーして使える（README の「インデックスを別の PC で使う」）。利用者の明示操作だが、設計上の持ち出し経路である |
| 残留 | `work/` を消さない限りインデックスは残る。元のファイルを削除しても、インデックス側の本文は次の変換まで残る |

運用での対策（導入時に決めることを推奨）:

- ツールを置いたフォルダのアクセス権を、**変換対象フォルダと同等以上に制限する**。
- 権限の異なる利用者が読める共有フォルダに、インデックスをそのまま置かない（`work/index/` を各利用者のローカルに置く）。
- 持ち出し（別 PC へのコピー）の可否を運用ルールで決める。
- ディスク暗号化（BitLocker）を前提にする。

本ツール側では、インデックスの場所を `work/` 配下に限定し、アクセス権の変更（`Set-Acl` 等）を一切行わない。したがって**インデックスの保護は設置フォルダのアクセス権で決まる**。

### 4.4 原本の一時コピーと、その回収

変換中は、原本のコピーを `%TEMP%\win_grep\<PID>` に作る（3.2）。機密文書のコピーが一時的に `%TEMP%` に存在することになるため、扱いを明記する。

- **通常終了時**: 変換の完了時にファイルを削除し、作業フォルダごと削除する（`removeTmpDir`）。
- **異常終了時**: 強制終了・停電などでコピーが残ることがある。この場合、**次回の変換開始時に、終了済みのプロセスの作業フォルダをまとめて削除する**（`win_grep/convert/index_migrate.ps1:29` の `removeStaleTmpDirs`。`win_grep/convert.ps1:95` で起動時に呼ぶ）。
- **残る期間**: 異常終了から次回の変換開始までの間は残る。気になる場合は `%TEMP%\win_grep` を手で削除してよい（動作に影響しない）。

### 4.5 変換中に Excel が前面に出る場合

検索結果から元の Excel ファイルを開く際、Excel を可視化して前面に出す（`win_grep/ui/open_source.ps1:161`・`212`）。これは利用者が開くよう操作したときの動作である。変換処理側の Office は常に不可視（`Visible = $false`）で動作する。

## 5. 第三者のツールによる検査結果

本ツールの作者以外が作ったツールでの検査結果を示す。5.1〜5.4 は誰でも同じコマンドで再現できる。

### 5.1 配布物の完全性（カタログ・ハッシュ一覧）

Windows PowerShell 5.1 標準の `New-FileCatalog` で、配布物の全ファイルの SHA256 を 1 つのカタログ（`.cat`）にまとめられる。**証明書は不要**で、受け取った側は配布時点から 1 バイトも変わっていないことを自分で確認できる。

```powershell
# 配布側: カタログとハッシュ一覧を作る（work\release\ に出力）
.\tools\new_release_files.ps1

# 受け取り側: 配布物が改ざんされていないことを確認する
Test-FileCatalog -Path .\scripts, .\win_grep.bat -CatalogFilePath .\win_grep.cat -Detailed
```

実施結果:

| 項目 | 値 |
|---|---|
| 対象ファイル数 | 51（`scripts/` 配下すべてと `win_grep.bat`） |
| 検証結果 | `Status: Valid`（改ざんなし） |
| 署名 | `NotSigned`（コードサイニング証明書を導入すれば、発行者の保証も付く） |
| ハッシュ方式 | SHA256（`-CatalogVersion 2`） |

`tools\new_release_files.ps1` は、カタログに加えて目視・比較しやすい `SHA256SUMS.txt` も出力する。配布 zip にこの 2 つを同梱する運用にすれば、審査側は受け取った配布物そのものを検証できる。

### 5.2 静的解析: PSScriptAnalyzer（Microsoft）

PowerShell スクリプトの静的解析ツール。Microsoft が公開しているルールで、コードインジェクション・平文パスワードなどを検出する。

```powershell
Install-Module PSScriptAnalyzer -Scope CurrentUser        # 未導入の場合

# 安全性にかかわるルールでの検査（0 件であることを確認する）
Invoke-ScriptAnalyzer -Path .\scripts -Recurse -Settings .\tests\meta\PSScriptAnalyzer.security.psd1

# 全ルールでの検査（書き方のルールを含む）
Invoke-ScriptAnalyzer -Path .\scripts -Recurse
```

実施結果（PSScriptAnalyzer 1.25.0）:

| 検査 | 結果 |
|---|---|
| 安全性にかかわる 14 ルール（`tests/meta/PSScriptAnalyzer.security.psd1`） | **指摘 0 件** |
| 全ルールのうち `Error` 重大度 | **指摘 0 件**（`TypeNotFound` を除く。下の注を参照） |
| 全ルール | 239 件（`Warning` 208 件 / `Information` 31 件。内訳は下表） |

有効にしている安全性のルールは次の 14 件である。設定ファイルからルールを削って「0 件」にする抜け道を防ぐため、この 14 件が設定に含まれていることも `tests/meta/safety.Tests.ps1` で検査している。

| 分類 | ルール |
|---|---|
| 文字列を式として実行しない | `PSAvoidUsingInvokeExpression` |
| パスワード・資格情報の平文の扱い | `PSAvoidUsingPlainTextForPassword`・`PSAvoidUsingConvertToSecureStringWithPlainText`・`PSUsePSCredentialType`・`PSAvoidUsingUsernameAndPasswordParams` |
| 通信先の固定・暗号化されない通信 | `PSAvoidUsingComputerNameHardcoded`・`PSAvoidUsingAllowUnencryptedAuthentication` |
| 危険・非推奨な API | `PSAvoidUsingBrokenHashAlgorithms`・`PSAvoidUsingWMICmdlet` |
| 標準コマンドの上書き・別名の定義 | `PSAvoidOverwritingBuiltInCmdlets`・`PSAvoidGlobalAliases`・`PSReservedCmdletChar`・`PSReservedParams` |
| 文字コード | `PSUseBOMForUnicodeEncodedFile` |

全ルールで出る 239 件の内訳は次のとおりで、**すべて書き方（可読性・保守性）のルール**である。安全性の判断には関わらない。

| 件数 | ルール | 内容と本ツールでの理由 |
|---|---|---|
| 58 | `PSAvoidUsingWriteHost` | `Write-Host` で画面・ログへ出力している。変換処理の進み具合と失敗の原因を利用者に見せるための出力であり、パイプラインへ返す値ではない |
| 49 | `PSUseDeclaredVarsMoreThanAssignments` | `-ErrorVariable` で受け取る変数、`${...}` 記法で別ファイルから参照する変数など、別の構文で使う変数 |
| 42 | `PSReviewUnusedParameter` | 画面のイベントハンドラーの引数（`sender`・`e`）など、WPF の呼び出し規約で受け取るだけの引数 |
| 34 | `PSAvoidUsingEmptyCatchBlock` | 権限の無いプロセスの起動時刻が取れない場合など、失敗しても処理を続けるべき箇所。理由は各 `catch` にコメントで記載している |
| 26 | `PSAvoidUsingPositionalParameters` | COM の呼び出し（`Workbooks.Open` 等）は引数の順序が API 側で決まっており、名前付きにできない |
| 25 | `PSAvoidAssignmentToAutomaticVariable` | WPF のイベントハンドラーの引数名 `sender` に対する指摘。PowerShell の自動変数と同名だが、ハンドラー内の引数であり影響しない |
| 5 | `TypeNotFound` | `win_grep/ui/types_grep.ps1` が、`shared/ui/types.ps1` の型（`NotifyBase`）を継承しているため。1 ファイルだけを解析すると継承元が見つからないという指摘で、実際の読み込み順では解決する（`tests/meta/structure.Tests.ps1` の「型の読み込み」で実際に読み込んで確認している） |

なお `tests/testdata/make_testdata.ps1` には `PSAvoidUsingPlainTextForPassword` の指摘が 7 件出る。パスワード付きの Office ファイルを**テストデータとして作る**スクリプトであり、パスワードは固定のテスト用文字列である。利用者へ配布する `scripts/` には含まれない。

### 5.4 実行環境の制約との適合

アプリケーション制御を強制している環境で動くかどうかは、安全性の間接的な指標になる（制限された環境で動くコードは、危険な機能を使っていない）。

| 指標 | 結果 | 確認コマンド |
|---|---|---|
| 制限言語モード（Constrained Language Mode）で使えない書き方 | **指摘 0 件**（`TypeNotFound` を除く） | `Invoke-ScriptAnalyzer -Path .\scripts -Recurse -IncludeRule PSUseConstrainedLanguageMode` |
| Windows PowerShell 5.1 の構文互換 | **指摘 0 件** | `Invoke-ScriptAnalyzer -Path .\scripts -Recurse -IncludeRule PSUseCompatibleSyntax -Settings @{ Rules = @{ PSUseCompatibleSyntax = @{ Enable = $true; TargetVersions = @('5.1') } } }` |
| AppLocker・WDAC との相性 | 実行時コンパイル（`csc.exe`）を行わないため、一時 DLL の生成でブロックされることがない（2.1） | – |

ただし実際に制限言語モードを強制した環境では、COM オブジェクトの生成が制限されるため、**実動確認は別に必要**である（本ツールは Excel の COM を使う）。

攻撃面の縮小（ASR）ルールとの関係も整理しておく。

| ASR ルール | 本ツールへの影響 |
|---|---|
| Office アプリが子プロセスを作るのをブロック | **該当しない**。本ツールは逆方向（PowerShell が Office を起動する）であり、Office 側から子プロセスを作らない |
| 潜在的に難読化されたスクリプトの実行をブロック | 該当しない想定（難読化を行わないため）。導入先で有効な場合は、まず監査モードで 1 回通し実行して確認することを推奨。**このルールが通ることは、Microsoft のヒューリスティックが難読化と判定しないことの証拠にもなる** |
| Office マクロからの Win32 API 呼び出しをブロック | 該当しない。マクロを強制無効で開く（2.2） |

### 5.5 実行時の観測（動作の記録による確認）

「コードを読んだ結果」よりも「動かして記録した結果」のほうが強い証拠になる。導入先の環境で 1 回実施すれば、2 章・3 章の主張を実測で裏付けられる。
