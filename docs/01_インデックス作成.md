## 1. 概要

画面で登録したクロール対象フォルダ（`setting.config`。複数可。チェックを付けたフォルダだけ）配下の Office ファイル（Excel・Word・PowerPoint）を、シート・ページ・スライドごとにテキストを抽出して TSV に書き出し、フォルダ・拡張子ごとのまとめファイルにまとめて `work/index/<インデックス名>/` に保存する（6.1）。

| 種類 | 拡張子 | 抽出方法 | 場所（TSV の単位） |
|---|---|---|---|
| Excel | `.xlsx` `.xlsm` `.xls` `.xlsb` | Excel の COM 操作でシートごとにテキスト保存（セルの表示値を得るため） | シート |
| Word | `.docx` `.docm` | ファイル（ZIP 内の XML）を直接読む。Word は使わない | ページ（目安）・ヘッダー/フッター・脚注 |
| Word（旧形式） | `.doc` | Word で `.docx` に変換してから、上と同じ方法で読む | 同上 |
| PowerPoint | `.pptx` `.pptm` | ファイル（ZIP 内の XML）を直接読む。PowerPoint は使わない | スライド・ノート |
| PowerPoint（旧形式） | `.ppt` | PowerPoint で `.pptx` に変換してから、上と同じ方法で読む | 同上 |

いずれも元のファイルは直接開かず、作業領域（`%TEMP%\tebunko_grep\<PID>`）にコピーしてからコピーを開く・読む（元のファイルを占有しない。`copyFileShared`）。インデックス作成中も、ほかの利用者が元のファイルを開いて編集・上書き保存できる。

- クロール対象フォルダは複数登録でき、チェックを付けたフォルダだけを取り込む。チェックを外したフォルダは取り込まないが、インデックスは残す。
- クロール対象フォルダ配下の全ファイルの更新日時・サイズ・状態を `work/取り込み一覧.tsv` に記録し、前回から更新されたファイル・未取り込みのファイルだけを取り込む（差分取り込み）。
- 利用者に入力を求めない（コンソールで確認・キー入力を待たない）。画面から起動した場合（`-ConfirmTargets`）は、**取り込み対象を数えたところでいったん止まり、インデックスごとの件数を画面に出して取り込むかどうかの返事を待つ**（4.2）。前回失敗したファイルを再取り込みするかも、この確認で受け取る（コンソールから直接実行する場合は `-RetryFailed` で渡す）。
- 画面の［中止］で中止した場合、次回は未処理のファイルから再開する。インデクサが強制終了された（PC が停止した等）場合も同様で、強制終了したときに取り込んでいたファイルは最後に回す（4.2）。
- 1 ファイルの取り込みが制限時間（10 分）を超えたら、Office アプリを強制終了してそのファイルを「失敗」とし、次のファイルへ進む（応答しなくなったファイルで止まり続けないため。4.2）。
- 取り込みに失敗したファイルは取り込み一覧の状態を「失敗」とし、更新されない限り次回以降はスキップする（画面で「失敗分も再取り込みする」を選ぶと再取り込みする）。
- 元ファイルが無くなったファイルは、インデックス（まとめファイル）から外して取り込み一覧から除く。
- Excel・Word・PowerPoint は必要になったときだけ起動する（Word・PowerPoint は旧形式などの変換時のみ）。

## 2. 入出力

| 区分 | パス | 内容 |
|---|---|---|
| 入力 | `setting.config` の `targetFolders` | クロール対象フォルダ（チェックの有無を含む。3 章） |
| 入力 | クロール対象フォルダ配下の Office ファイル | `.xlsx` `.xlsm` `.xls` `.xlsb` `.docx` `.docm` `.doc` `.pptx` `.pptm` `.ppt` |
| 入出力 | `work/取り込み一覧.tsv` | 全ファイルの更新日時・サイズ・状態（4.2） |
| 入出力 | `work/取り込み中.txt` | 取り込み中のファイル。取り込みが終われば削除する。残っていれば、そのファイルの取り込み中に強制終了した（4.2） |
| 出力 | `work/インデックス作成進捗.txt` | 進み具合の 1 行（段階・処理済み・残り・失敗・いま行っていること）。画面はこれだけを読んで進み具合を表示する（4.1） |
| 入力 | `work/インデックス作成中止要求` | 画面の［中止］・確認の［キャンセル］で作成される。見つけたら削除して中止する（4.1） |
| 出力 | `work/取り込み予定.tsv` | `-ConfirmTargets` のとき、数えたインデックスごとの取り込み対象の件数（画面の確認に出す）。返事を受け取ったら削除する（4.2） |
| 入力 | `work/インデックス作成開始要求` | 画面の確認で［インデックス作成を開始］が押されると作成される。中身で、前回失敗したファイルも再取り込みするかを受け取る（4.2） |
| 出力 | `work/インデックス作成エラー.txt` | 続けられないエラーのメッセージ（終了コード 1）。開始時・正常終了時には無い（4.1） |
| 出力 | `work/インデックス作成ログ.txt` | 表示内容の記録（`Start-Transcript`。実行ごとに上書き） |
| 作業領域 | `%TEMP%\tebunko_grep\<PID>\` | 取り込み途中のファイル（元のファイルのコピー・変換したファイル・TSV）。終了時に削除する |
| 作業領域 | `work/取り込み出力/<PID>/` | 1 ファイル分の TSV を集めてからインデックスのフォルダと入れ替えるための場所（6.1）。終了時に削除する |
| 出力 | `work/index/<インデックス名>/<相対フォルダ>/content.<拡張子>.tsv` | フォルダ・元のファイルの拡張子ごとのまとめファイル（6 章）。インデックス名はクロール対象フォルダごと。取り込み中だけ、シート・ページ・スライドごとの TSV（`<相対フォルダ>/<ファイル名>/*.tsv`）を置く |
| 出力 | `work/index/<インデックス名>/元のフォルダ.txt` | インデックス名とクロール対象フォルダの対応（4.2）。インデックスを別の PC・場所へコピーしても、検索結果から元のファイルを開けるようにする |

## 3. クロール対象フォルダ（`getTargetFolders`）

クロール対象フォルダは、画面（`tebunko_grep.bat`）の［1 インデックス管理］でチェックボックス付きの一覧として登録し、`setting.config` の `targetFolders` に保存する（`writeTargetFolders`。形式は [00_共通_1_フォルダ構成と設定ファイル.md 4 章](00_共通_1_フォルダ構成と設定ファイル.md#4-設定ファイル-settingconfigreadsettings)）。チェックを外したフォルダ（`enabled` が `false`）は、登録はしておくが取り込まない。インデクサは開始時にこれを読む。

- パスは 1 つの書き方にそろえる（`normalizeFolderPath`）。エクスプローラーの「パスのコピー」をそのまま貼り付けられる。
  - 前後の空白・`"` と末尾の `\` を取り除く（ドライブ直下は `D:\` のまま、UNC の共有直下は `\\server\share`）。
  - 環境変数（`%USERPROFILE%` など）を展開し、`/` を `\` にそろえ、長いパス用の `\\?\` ・ `\\?\UNC\` を外し、重なった `\` ・ `.` ・ `..` を解決する。
  - 相対パス（`work\index` など）は tebunko_grep のフォルダからとみなして絶対パスにする。
  - パスとして解釈できない場合（`*` `?` を含む・共有名の無い `\\server` ・ `\` ひとつで始まる）は、書かれたとおりに扱う（存在しないフォルダになる）。
- 同じフォルダ（大文字・小文字、末尾の `\` の違いを含む）が複数あれば、最初のものだけを使う。
  ネットワークドライブと UNC パス（`Z:\見積` と `\\server\share\見積`）、`subst` のドライブと割り当て元のフォルダのように、
  **書き方が違うだけで同じ場所を指す場合も同じフォルダとみなす**（`testSameFolder`。ドライブの割り当ては CIM（`Win32_LogicalDisk`）で調べる）。
  ファイルサーバーのフォルダを、あるときはドライブ文字、あるときは UNC パスで登録しても、インデックスが二重にならない。
- フォルダが 1 つも無い場合は例外: `クロール対象フォルダがありません。画面でクロール対象フォルダを追加してください。`
- チェックの付いたフォルダが無い場合は例外: `チェックの付いたクロール対象フォルダがありません。画面で取り込むフォルダにチェックを付けてください。`
- チェックの付いたフォルダが存在しない場合は、そのフォルダだけ取り込まずに続行する（`… フォルダが見つからないため取り込みません` と黄色で表示）。ネットワークドライブが切断されている場合などに、既存のインデックスを消さないため。

| 操作 | インデックス作成時の動作 |
|---|---|
| フォルダを追加（チェックあり） | 新しいインデックス名を割り当てて取り込む |
| チェックを外す | 取り込まない。インデックスと取り込み一覧の行はそのまま残る（検索対象にも残る） |
| チェックを付け直す | 前回と同じインデックス名で、更新されたファイルだけ取り込む |
| 一覧から削除 | `work/index/<インデックス名>` を丸ごと削除し、取り込み一覧からも除く（`クロール対象から削除されたフォルダ（<パス>）のインデックスを削除しました。`） |
