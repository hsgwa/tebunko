## 6. 状態の判定と表示

### 6.1 インデックスとインデックス作成の状態

| 状態 | 判定方法 | ［インデックス管理］No.6 の表示 | 起動時のタブ |
|---|---|---|---|
| 未作成 | 検索対象インデックスに TSV が無い | `まだインデックスがありません。` | 1 |
| 中断中 | `work/取り込み一覧.tsv` に状態が `未取り込み` の行がある | `⏸ 前回のインデックス作成が中断しています（残り N 件）` | 1 |
| 失敗あり | `work/取り込み一覧.tsv` に状態が `失敗` の行がある | 「取り込みに失敗したファイル」の一覧（`⚠ 取り込みに失敗したファイル N 件`。ファイルごとに失敗の原因を表示） | 2（タブ見出しに ⚠） |
| インデックス作成中 | この画面から起動したインデックス作成（`tebunko_grep/indexer.ps1`）のプロセス、または起動時・開始時に見つけた実行中のインデックス作成のプロセスが動いている（3.1） | `インデックス作成中…` | 1 |
| 通常 | 上のいずれでもない | `取り込み済み N ファイル（TSV M 件 ・ 最終取り込み M/d H:mm）` のみ | 2 |

- 「最終取り込み」は、インデックス配下の TSV の最新の更新日時とする。
- 「インデックス作成中」は、画面の起動時と［インデックス作成を開始］を押したときに、このツールの `scripts\tebunko_grep\indexer.ps1` を実行中の `powershell.exe` を探して判定する（3.1）。見つかれば、そのプロセスの進み具合を表示し、二重に起動しない。

### 6.2 インデックス作成の状態遷移（画面から見た状態）

```mermaid
stateDiagram-v2
    direction LR
    state "未作成" as None
    state "通常" as Ready
    state "インデックス作成中" as Running
    state "中断中" as Suspended
    state "失敗あり" as HasError

    [*] --> None
    None --> Running : インデックス作成を開始<br>（確認で［インデックス作成を開始］）
    Ready --> Running : インデックス作成を開始<br>（確認で［インデックス作成を開始］）
    Suspended --> Running : 続きから再開
    HasError --> Running : インデックス作成を開始<br>（確認で失敗分も再取り込みするかを選ぶ）
    Running --> Ready : 全件成功
    Running --> HasError : 失敗あり
    Running --> Suspended : ［中止］<br>プロセス停止・PC の停止
    Running --> Ready : 確認で［キャンセル］<br>更新不要（取り込むものが無い）
```

### 6.3 状態を読み直すタイミング

- 起動時、タブを切り替えたとき、ウィンドウがアクティブになったとき、起動したインデックス作成のプロセスが終了したとき。
- TSV の件数は、インデックスが大きいと数えるのに時間がかかるため、別スレッド（Runspace）で数える。数え終わるまでは `確認中…` と表示し、その間も画面を操作できるようにする。

## 7. 操作の流れ

### 7.1 検索

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant S as 検索スレッド（searchIndex）
    participant I as 検索対象インデックス

    U->>G: ワードを入力して Enter
    G->>G: 入力チェック（ワードが空でない・TSV 1 件以上）
    G->>S: 検索開始（ワード・検索条件・検索対象フォルダ）
    G->>G: ［検索］→［中止］、結果の表をクリア
    loop 100 ファイルごと
        S->>I: .NET（StreamReader＋[regex]）で読み込み・照合
        S-->>G: 結果と進捗
        G->>G: 表に追加、「検索中… N / M ファイル」
    end
    S-->>G: 完了
    G->>G: 「N 件（M ファイル） ・ X 秒」、［中止］→［検索］
    U->>G: 結果をダブルクリック
    G->>G: 元のファイルの該当箇所を開く（4.5）
```

### 7.2 インデックス作成

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant C as setting.config
    participant W as work/
    participant P as tebunko_grep/indexer.ps1（ウィンドウなし）

    U->>G: ［インデックス作成を開始］など（3.1）
    G->>G: 実行中のインデックス作成を探す（あればその進み具合を表示して終わり）
    G->>C: インデックス一覧を保存
    G->>P: 起動（-WindowStyle Hidden -ConfirmTargets）
    G->>G: 実行ボタンを無効化、「インデックス作成中…」、［中止］を表示
    P->>W: 取り込み対象を数えて 取り込み予定.tsv を書き、返事を待つ
    G->>W: 取り込み予定.tsv を読む
    G->>U: インデックス作成の確認（インデックスごとの件数。3.4）
    alt ［インデックス作成を開始］
        U->>G: （前回失敗分も再取り込みするかを選ぶ）
        G->>W: インデックス作成開始要求 を作る
    else ［キャンセル］
        U->>G: 取りやめ
        G->>W: インデックス作成中止要求 を作る
        P-->>G: 1 件も取り込まずに終了（終了コード 2）
    end
    loop 1 秒ごと（プロセスが終わるまで）
        P->>W: TSV を作成、取り込み一覧・インデックス作成進捗.txt を更新
        G->>W: インデックス作成進捗.txt を読む
        G->>G: 進み具合を表示（3.6）
    end
    opt ［中止］
        U->>G: ［中止］→［はい］
        G->>W: インデックス作成中止要求 を作る
        P->>W: 取り込み中のファイルが終わったら止まる
    end
    P-->>G: プロセス終了（終了コード 0 / 1 / 2）
    G->>G: 終了コードに応じた表示、［ログを開く］（3.7）
    G->>W: 状態を読み直す（6.1）
```

### 7.3 プロセス停止

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant O as Office プロセス

    U->>G: ［9 プロセス停止］タブを開く
    G->>O: 一覧を取得（getOfficeProcesses）
    G->>G: 表を表示
    U->>G: ［バックグラウンドのみ終了］など
    G->>U: 確認（5.2）
    U->>G: はい
    G->>O: Stop-Process -Force
    G->>O: 一覧を取り直す
    G->>G: 「N 個のプロセスを終了しました。」
```

### 7.4 閉じる

- 閉じるのはタイトルバーの［×］（または Alt+F4）で行う。画面に［閉じる］ボタンは置かない。
- 設定はその場で保存しているため、保存の確認は無い。
- 検索中なら検索を中止してから閉じる。
- インデックス作成中なら、インデックス作成を中止してから閉じるか、続けたまま閉じるかを確認する（3.7）。続けたまま閉じた場合、次に画面を開くと実行中のインデックス作成を見つけて進み具合を表示する。
