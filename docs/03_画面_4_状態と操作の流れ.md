## 6. 状態の判定と表示

画面がインデックスとインデックス作成の状態をどう判定して見せるか（6 章）と、検索・インデックス作成・プロセス停止・終了の操作の流れ（7 章）をまとめる。

### 6.1 インデックスとインデックス作成の状態

| 状態 | 判定方法 | ［1 インデックス管理］の表示 | 起動時のタブ |
|---|---|---|---|
| 未作成 | `work/index` に集約ファイルが無い | No.5 に `まだインデックスがありません。` | 1 |
| 中断中 | `work/取り込み一覧.tsv` に状態が `未取り込み` の行がある | No.5 の次の行に `⏸ 前回のインデックス作成が中断しています（残り N 件）`、No.6 のボタンは［続きから再開（残り N 件）］ | 1 |
| 失敗あり | `work/取り込み一覧.tsv` に状態が `失敗` の行がある | 「取り込みに失敗したファイル」の一覧（`⚠ 取り込みに失敗したファイル N 件`。ファイルごとに失敗の原因を表示） | 2（タブ見出しに ⚠） |
| インデックス作成中 | この画面で始めたインデックス作成のスレッド（`IndexingSession`）が動いている（`isIndexing`。3.3） | No.6 のボタンが `インデックス作成中…`（無効）。進み具合（3.6） | 1 |
| 通常 | 上のいずれでもない | No.5 に `取り込み済み N ファイル（集約ファイル M 件 ・ 最終取り込み M/d H:mm）` のみ | 2 |

- 「最終取り込み」は、インデックス配下の集約ファイルの最新の更新日時とする。
- 「インデックス作成中」は、この画面で始めたインデックス作成のスレッドが動いているかで判定する。インデックス作成は画面のプロセスの中で動くため、画面を開いたときに動いているものは無い。画面を使わずに起動した `indexer.ps1` と重なったときは、インデクサがミューテックスで二重に動かないようにする（[01_インデックス作成_4](01_インデックス作成_4_メインフローと取り込み一覧.md#41-メインフロー)）。

### 6.2 インデックス作成の状態遷移（画面から見た状態）

```mermaid
stateDiagram-v2
    direction LR
    state "未作成" as None
    state "通常" as Ready
    state "インデックス作成中" as Running
    state "中断中" as Suspended
    state "失敗あり" as HasError

    [*] --> None
    None --> Running : インデックス作成を開始<br>（確認で［インデックス作成を開始］）
    Ready --> Running : インデックス作成を開始<br>（確認で［インデックス作成を開始］）
    Suspended --> Running : 続きから再開
    HasError --> Running : インデックス作成を開始<br>（確認で失敗分も再取り込みするかを選ぶ）
    Running --> Ready : 全件成功
    Running --> HasError : 失敗あり
    Running --> Suspended : ［中止］・止めて閉じる<br>プロセス停止・PC の停止
    Running --> Ready : 確認で［キャンセル］<br>更新不要（取り込むものが無い）
```

### 6.3 状態を読み直すタイミング

- 起動時、タブを切り替えたとき、ウィンドウがアクティブになったとき、始めたインデックス作成が終わったとき。
- 集約ファイルの件数は、インデックスが大きいと数えるのに時間がかかるため、画面の裏の仕事のスレッド（`startJob`。`BackgroundQueue`）で数える。数え終わるまでは `確認中…` と表示し、その間も画面を操作できるようにする。

## 7. 操作の流れ

### 7.1 検索

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant S as 検索の司令（SearchService）
    participant P as 照合のプール
    participant I as 検索対象インデックス

    U->>G: ワードを入力して Enter
    G->>G: 入力チェック（ワードが空でない・集約ファイル 1 件以上・検索対象にチェックあり）
    G->>S: 検索の要求を渡す（newSearchRequest。前の要求は Stop で取り消す）
    G->>G: ［検索］→［中止］、結果の表をクリア
    loop 作業（約 16MB）ごと
        S->>P: 作業を渡す
        P->>I: .NET（StreamReader＋[regex]）で読み込み・照合
        P-->>S: ヒット
        S-->>G: 要求の列にヒットと進み具合を入れる
        G->>G: 時間で区切って列から取り出し（pumpSearch）、ファイルの見出しを表に追加、「検索中… N / M ファイル（K 件）」
    end
    S-->>G: 完了（Finished）
    S->>S: 読んだ内容のキャッシュを整理（trimTsvTextCache）
    G->>G: 「N 件（M ファイル） ・ X 秒」、［中止］→［検索］
    U->>G: 見出しをクリックして行を開き、行をダブルクリック
    G->>G: 元のファイルの該当箇所を開く（4.5）
```

- 検索の司令と照合のプールは、画面を開いている間使い回す（[7.3](00_共通_4_プロセスとスレッド.md#73-寿命)）。

### 7.2 インデックス作成

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant C as setting.config
    participant K as 受け渡しの口（メモリ）
    participant P as インデクサの司令のスレッド（indexer.ps1 -Channel）
    participant W as work/


    U->>G: ［インデックス作成を開始］など（3.3）
    G->>C: インデックス一覧を保存
    G->>P: スレッドで実行（IndexingSession。受け渡しの口の ConfirmTargets）
    G->>G: 実行ボタンを無効化、「インデックス作成中…」、［中止］を表示
    P->>K: 取り込み対象を数えて取り込み予定（Plan）を入れ、返事を待つ
    G->>K: 取り込み予定を読む
    G->>U: インデックス作成の確認（インデックスごとの件数。3.4）
    alt ［インデックス作成を開始］
        U->>G: （前回失敗分も再取り込みするかを選ぶ）
        G->>K: 取り込む返事（answerIndexingPlan）
    else ［キャンセル］
        U->>G: 取りやめ
        G->>K: 取りやめの返事（answerIndexingPlan $null）
        P-->>G: 1 件も取り込まずに終了（終了コード 2）
    end
    loop 1 秒ごと（スレッドが終わるまで）
        P->>W: 取り込みのスレッドで TSV を作成し、フォルダごとに集約ファイルに入れ、取り込み一覧を更新
        P->>K: 進み具合（Progress）を入れる
        G->>K: 進み具合を読む
        G->>G: 進み具合を表示（3.6）
    end
    opt ［中止］
        U->>G: ［中止］→［中止する］
        G->>K: 中止（requestIndexingStop）
        P->>W: 取り込み中のファイルが終わったら止まる
    end
    P-->>G: スレッドの終了（受け渡しの口の ExitCode 0 / 1 / 2・Error）
    G->>G: 終了コードに応じた表示、［ログを開く］（3.7）
    G->>W: 状態を読み直す（6.1）
```

### 7.3 プロセス停止

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant O as Office プロセス

    U->>G: ［9 プロセス停止］タブを開く
    G->>O: 一覧を取得（getOfficeProcesses）
    G->>G: 表を表示
    U->>G: ［バックグラウンドのみ終了］など
    G->>U: 確認（5.2）

    G->>O: Stop-Process -Force
    G->>O: 一覧を取り直す

```

### 7.4 閉じる

- 閉じるのはタイトルバーの［×］（または Alt+F4）で行う。画面に［閉じる］ボタンは置かない。
- 設定はその場で保存しているため、保存の確認は無い。
- 検索中なら検索を取り消してから閉じる。
- インデックス作成は画面のプロセスの中で動くため、画面を閉じるときは止める。インデックス作成を続けたまま画面だけを閉じることはできない。

インデックス作成中に閉じようとすると、確認ダイアログ（[10.2](03_画面_5_共通仕様.md#102-確認ダイアログshowconfirm)）を出す。

| 項目 | 内容 |
|---|---|
| 見出し | `まだインデックス作成の途中です。止めてから閉じますか？` |
| 結果の行 | `→ いま取り込んでいるファイルが終わったところで止まり、画面を閉じます`、`✓ ここまで取り込んだ分はそのまま残ります`（詳細: `次に開いて［インデックス作成を開始］を押すと、続きから再開します`） |
| 選択肢 | ［インデックス作成を止めて閉じる］／［閉じない］ |

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant G as 画面
    participant P as インデクサ（IndexingSession）
    participant S as 検索・画面の裏の仕事

    U->>G: ［×］
    alt インデックス作成中
        G->>U: 止めてから閉じるか確認（［閉じない］なら閉じずに終わる）
        U->>G: ［インデックス作成を止めて閉じる］
        G->>G: 閉じるのを保留。進み具合欄に「インデックス作成を止めています…」
        G->>P: 中止（Stop）
        loop 0.5 秒ごと（closeTimer）
            G->>P: 終わったか（IsRunning）
        end
        opt 60 秒たっても終わらない
            G->>P: インデックス作成が起動した Office だけを止める（KillOffice）
        end
        opt さらに 15 秒たっても終わらない
            G->>G: 待つのをやめる
        end
        P-->>G: 終了
    end
    G->>S: 検索を取り消す
    G->>G: closeTimer・インデックス作成のタイマーを止める
    G->>P: スレッドを片づける（IndexingSession.Close）
    G->>S: 検索の司令・照合のプールを閉じる（SearchService.Close）
    G->>S: jobTimer を止め、画面の裏の仕事のスレッドを閉じる（BackgroundQueue.Close）
    G->>G: 多重起動のミューテックスを解放
    G->>U: 閉じる
```

- 確認している間にインデックス作成が終わっていれば、［インデックス作成を止めて閉じる］でそのまま閉じる。
- 止めるのを待っている間にもう一度［×］を押しても、何もしない。
- 60 秒待っても終わらないのは、Office が応答しないときである。止めるのは、インデックス作成が起動して PID を記録した Office だけで、利用者が開いていた Office は止めない（[7.6](00_共通_4_プロセスとスレッド.md#76-閉じるときの順番)）。
