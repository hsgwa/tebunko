# インデックス作成（インデクサ）

クロール対象フォルダの Office ファイル（Excel・Word・PowerPoint）から文字を抽出し、検索用のインデックス（TSV）を作るインデクサの設計書。このページは概要・入出力・クロール対象フォルダを扱い、処理の詳細は下の「この区分のページ」の各ページに分ける。

## インデックスとは（はじめて読む方へ）

**インデックス**は、Office ファイルから抽出した文字列を、検索用に前もって保存した索引データである。書籍の巻末索引と同様に、検索のたびに元のファイルを開く処理を省くために用いる。利用者向けの説明は [インデックスの仕組み](../../guide/about-index.md) にある。本節では、インデックスの内容を具体例で示す。

**例**: `C:\共有\営業部\見積\(株)山田商事_見積書.xlsx` に「見積」シートがあり、1 行目に `品名 数量 単価`、2 行目に `りんご 10 100` と書いてあるとする。

```mermaid
flowchart LR
    X["(株)山田商事_見積書.xlsx<br>シート「見積」"] -- "① 取り込み<br>Excel でシートを<br>テキストに書き出す" --> T["場所ごとの TSV<br>（1 行 = Excel の 1 行）"]
    T -- "② フォルダの取り込みが<br>終わったら集約" --> P[("集約ファイル<br>index/営業部/見積/<br>content.xlsx.001.tsv")]
    P -- "③ 検索は<br>集約ファイルだけを読む" --> R["結果: (株)山田商事_見積書.xlsx<br>見積・2 行目「りんご…」"]
```

1. **取り込み**：元のファイルのコピーを開き、シート・ページ・スライドなどの**場所**ごとに、文字を TSV（タブ区切りのテキスト）に書き出す。1 行が Excel の 1 行（Word・PowerPoint では段落 1 つ）にあたるので、検索結果に「何行目か」を出せる。
2. **集約**：フォルダの取り込みが終わると、そのフォルダの TSV を、フォルダ・拡張子ごとの**集約ファイル**にまとめる。集約ファイルには、どのファイルのどの場所かを示す行（メタ情報の行）と、TSV の中身が並ぶ。

    ```
    ␞ ファイル名=(株)山田商事_見積書.xlsx
    ␞ 種類=Excel
    ␞ シート=見積
    ␞ 対象=本文
    品名→数量→単価
    りんご→10→100
    ```

    （`␞` はメタ情報の行の印、`→` はタブ。形式の詳細は [インデックスの形式](index-format.md#集約ファイルの形式pack_formatps1)）
3. **検索**：検索は集約ファイルだけを順に読んで照合する。ファイル 1 つにつき 1 回開くのではなく、大きな集約ファイルをまとめて読むので速い（[検索の実装（速度）](../search/index.md#検索の実装速度)）。

インデックスは、ワークスペース（既定は `%USERPROFILE%\Documents\tebunko_ws`。設計書では `work/` と書く）に置く次のものでできている。

| もの | 置き場所 | 役割 |
|---|---|---|
| 集約ファイル | `work/index/<インデックス名>/<フォルダ>/content.<拡張子>.<番号>.tsv` | 検索が読む本体。**インデックス名**は、画面で登録したフォルダ（クロール対象フォルダ）1 つごとの名前 |
| 取り込み一覧 | `work/取り込み一覧.tsv` | どのファイルを、いつ、どの版で取り込んだか。2 回目からは、ここと比べて新しいファイル・変わったファイルだけを取り込む（差分取り込み） |
| システムインデックス | `work/system_index/` | 高速検索のために Windows Search に索引させる txt（[高速検索（Windows Search）](../search/fast-search.md)） |

インデックスは元のファイルから作り直せる。消しても元のファイルは失われず、次のインデックス作成ですべて取り込み直す。

| 項目 | 内容 |
|---|---|
| 起動 | 画面の［1 インデックス管理］タブの［インデックス作成を開始］（[［1 インデックス管理］タブ](../gui/index-tab.md)）。画面は自分のプロセスの中のスレッド（インデクサの司令）で `indexer.ps1 -Channel` を実行する（`IndexingSession`。[プロセスとスレッド](../architecture/threads.md)）。画面を使わずにコンソールから `indexer.ps1` を実行することもできる |
| スクリプト | `scripts/tebunko/indexer.ps1`（起動口）、`scripts/tebunko/indexer/indexer_run.ps1`（本体 `invokeIndexer`・取り込みのスレッド）、`scripts/shared/office/office_reader.ps1`（Word・PowerPoint の読み取り） |
| 引数 | `-RetryFailed`（省略可）: 前回失敗し、その後更新されていないファイルも再取り込みする<br>`-Channel`（省略可。画面から実行するときに渡す）: 受け渡しの口（`newIndexerChannel`）。取り込む前の確認・中止・進み具合・エラーはこれでやり取りする（確認するかは口の `ConfirmTargets`、失敗分の再取り込みは口の `RetryFailed` で決まる）。省略すると自分で口を作り、確認はせず、表示内容をコンソールにも出す |
| 終了コード | `0` 完了（ファイルごとの失敗は取り込み一覧に記録）/ `1` 続けられないエラー（内容は受け渡しの口の `Error` とログ）/ `2` 中止（確認で取りやめた場合を含む）。受け渡しの口の `ExitCode` にも入れる |
| 使用する共通関数 | `getTargetFolders` / `assignIndexNames` / `normalizeFolderPath` / `readStatusFile` / `writeStatusFile` / `addStatusRow` / `newStatusRow` / `formatFileTime` / `toSafeFileName` / `toIndexFileName` / `encodeIndexPlace` / `prettyTsv`（[共通モジュール](../architecture/modules.md)） |

全体構成・動作環境・フォルダ構成は [設計の概要](../index.md) を参照。

## 概要

画面で登録したクロール対象フォルダ（`setting.config`。複数可。チェックを付けたフォルダだけ）配下の Office ファイル（Excel・Word・PowerPoint）を、シート・ページ・スライドごとにテキストを抽出して TSV に書き出し、フォルダ・拡張子ごとの集約ファイルにまとめて `work/index/<インデックス名>/` に保存する（[配置・命名規則](index-format.md#配置命名規則)）。

| 種類 | 拡張子 | 抽出方法 | 場所（TSV の単位） |
|---|---|---|---|
| Excel | `.xlsx` `.xlsm` `.xls` `.xlsb` | Excel の COM 操作でシートごとにテキスト保存（セルの表示値を得るため） | シート |
| Word | `.docx` `.docm` | ファイル（ZIP 内の XML）を直接読む。Word は使わない | ページ（目安）・ヘッダー/フッター・脚注 |
| Word（旧形式） | `.doc` | Word で `.docx` に変換してから、上と同じ方法で読む | 同上 |
| PowerPoint | `.pptx` `.pptm` | ファイル（ZIP 内の XML）を直接読む。PowerPoint は使わない | スライド・ノート |
| PowerPoint（旧形式） | `.ppt` | PowerPoint で `.pptx` に変換してから、上と同じ方法で読む | 同上 |

いずれも元のファイルは直接開かず、作業領域（`%TEMP%\tebunko\<PID>`）にコピーしてからコピーを開く・読む（元のファイルを占有しない。`copyFileShared`）。インデックス作成中も、ほかの利用者が元のファイルを開いて編集・上書き保存できる。

- クロール対象フォルダは複数登録でき、チェックを付けたフォルダだけを取り込む。チェックを外したフォルダは取り込まないが、インデックスは残す。
- クロール対象フォルダ配下の全ファイルの更新日時・サイズ・状態を `work/取り込み一覧.tsv` に記録し、前回から更新されたファイル・未取り込みのファイルだけを取り込む（差分取り込み）。
- 利用者に入力を求めない（コンソールで確認・キー入力を待たない）。画面から実行した場合（受け渡しの口の `ConfirmTargets`）は、**取り込み対象を数えたところでいったん止まり、インデックスごとの件数を画面に出して取り込むかどうかの返事を待つ**（[取り込み一覧と取り込み対象の決定（差分・中断・再試行）](flow.md#取り込み一覧と取り込み対象の決定差分中断再試行)）。前回失敗したファイルを再取り込みするかも、この確認で受け取る（コンソールから直接実行する場合は `-RetryFailed` で渡す）。
- 画面の［中止］で中止した場合、次回は未処理のファイルから再開する。インデクサが強制終了された（PC が停止した等）場合も同様で、強制終了したときに取り込んでいたファイルは最後に回す（[取り込み一覧と取り込み対象の決定（差分・中断・再試行）](flow.md#取り込み一覧と取り込み対象の決定差分中断再試行)）。
- 1 ファイルの取り込みが制限時間（10 分）を超えたら、Office アプリを強制終了してそのファイルを「失敗」とし、次のファイルへ進む（応答しなくなったファイルで止まり続けないため。[取り込み一覧と取り込み対象の決定（差分・中断・再試行）](flow.md#取り込み一覧と取り込み対象の決定差分中断再試行)）。
- 取り込みに失敗したファイルは取り込み一覧の状態を「失敗」とし、更新されない限り次回以降はスキップする（画面で「失敗分も再取り込みする」を選ぶと再取り込みする）。
- 元ファイルが無くなったファイルは、インデックス（集約ファイル）から外して取り込み一覧から除く。
- Excel・Word・PowerPoint は必要になったときだけ起動する（Word・PowerPoint は旧形式などの変換時のみ）。
- 1 ファイルの取り込みは、ファイルの種類ごとのレーンで並べて行う。Excel・Word（`.doc`）・PowerPoint（`.ppt`）は、それぞれスレッド 1 つが Office を 1 つ持つ。`.docx`・`.pptx` などは、Office を使わない読み取りのスレッド（既定はコア数 − 1、最大 4。設定 `ingestThreads`）で読む（[インデックス作成の並列化](../architecture/threads.md#インデックス作成の並列化)）。

## クロール対象フォルダ（`getTargetFolders`）

クロール対象フォルダは、画面（`tebunko.bat`）の［1 インデックス管理］でチェックボックス付きの一覧として登録し、`setting.config` の `targetFolders` に保存する（`writeTargetFolders`。形式は [設定ファイル（setting.config）](../architecture/settings-file.md)）。チェックを外したフォルダ（`enabled` が `false`）は、登録はしておくが取り込まない。インデクサは開始時にこれを読む。

- パスは 1 つの書き方にそろえる（`normalizeFolderPath`）。エクスプローラーの「パスのコピー」をそのまま貼り付けられる。
  - 前後の空白・`"` と末尾の `\` を取り除く（ドライブ直下は `D:\` のまま、UNC の共有直下は `\\server\share`）。
  - 環境変数（`%USERPROFILE%` など）を展開し、`/` を `\` にそろえ、長いパス用の `\\?\` ・ `\\?\UNC\` を外し、重なった `\` ・ `.` ・ `..` を解決する。
  - 相対パス（`work\index` など）は tebunko のフォルダからとみなして絶対パスにする。
  - パスとして解釈できない場合（`*` `?` を含む・共有名の無い `\\server` ・ `\` ひとつで始まる）は、書かれたとおりに扱う（存在しないフォルダになる）。
- 同じフォルダ（大文字・小文字、末尾の `\` の違いを含む）が複数あれば、最初のものだけを使う。
  ネットワークドライブと UNC パス（`Z:\見積` と `\\server\share\見積`）、`subst` のドライブと割り当て元のフォルダのように、
  **書き方が違うだけで同じ場所を指す場合も同じフォルダとみなす**（`testSameFolder`。ドライブの割り当ては CIM（`Win32_LogicalDisk`）で調べる）。
  ファイルサーバーのフォルダを、あるときはドライブ文字、あるときは UNC パスで登録しても、インデックスが二重にならない。
- フォルダが 1 つも無い場合は例外: `クロール対象フォルダがありません。画面でクロール対象フォルダを追加してください。`
- チェックの付いたフォルダが無い場合は例外: `チェックの付いたクロール対象フォルダがありません。画面で取り込むフォルダにチェックを付けてください。`
- チェックの付いたフォルダが存在しない場合は、そのフォルダだけ取り込まずに続行する（`… フォルダが見つからないため取り込みません` と黄色で表示）。ネットワークドライブが切断されている場合などに、既存のインデックスを消さないため。

| 操作 | インデックス作成時の動作 |
|---|---|
| フォルダを追加（チェックあり） | 新しいインデックス名を割り当てて取り込む |
| チェックを外す | 取り込まない。インデックスと取り込み一覧の行はそのまま残る（検索対象にも残る） |
| チェックを付け直す | 前回と同じインデックス名で、更新されたファイルだけ取り込む |
| 一覧から削除 | `work/index/<インデックス名>` を丸ごと削除し、取り込み一覧からも除く（`クロール対象から削除されたフォルダ（<パス>）のインデックスを削除しました。`） |
