# PDF ファイルの読み取り

扱うこと: PDF ファイル（`.pdf`）から文字を読む範囲、読めない PDF の扱い、読み取りの上限、場所（ページ）の付け方、取り込みの流れ。扱わないこと: Office ファイルの取り込み（[クロール対象フォルダと取り込み対象](crawl.md)・[Excel](excel.md)）、テキストファイルの取り込み（[テキストファイルの読み取り](text.md)）、細工した PDF から身を守る確認（[安全性の確認の詳細](../../safety/checks.md)）。先に読むページ: [クロール対象フォルダと取り込み対象](crawl.md)、[取り込み対象の決定](target-decision.md)。

## 方針

PDF は PowerShell だけで読む（`shared/core/pdf_file.ps1`）。外の部品・ライブラリ・Office・外部プロセスは使わない。Office は起動しないので、取り込みは Office を使わない読み取りのレーン（`Reader`）で並べて行う。

画面にもファイルにも触らない関数（`readPdfPages`。バイト列からページごとの文字列を作る）と、ファイルを開いて読む関数（`readPdfFile`）に分ける。取り込みは `tebunko/indexer/extract_pdf.ps1` の `extractPdfFile` が行う。

## 取り込みの流れ

1. 元のファイルの大きさ（メタデータ。元は開かない）が上限（100MB）を超えるなら、コピーの前に失敗にする。
2. 元のファイルを読み取りだけ・共有モードで、作業領域の `source.copy` にコピーする（`copyFileShared`。元のファイルを書き込みの API に渡さない）。
3. コピーを読む（`readPdfFile`）。読み終えたら、TSV を書く前にコピーを消す（作業領域の中身は本文インデックスに回るため）。消せなかったときは失敗にする。
4. ページごとに場所 `ページ001` の TSV を書く（`addUnitLines`・`writeUnits`。Word と同じ書き方）。文字の無いページは TSV を作らない。
5. 本文インデックスには種類 `PDF` のファイルとして載る。画像だけの PDF（文字が 1 つも無い）は TSV が 0 個で、取り込み済み（`済`）になり、更新が無ければ取り込み直さない。

## 読む範囲

| 読む | 読まない（読めない PDF として失敗にする） |
|---|---|
| 相互参照の表・相互参照のストリーム（PNG の予測つきを含む）・オブジェクトのストリーム | 暗号化された PDF |
| 圧縮なし、`FlateDecode` | `FlateDecode` 以外の圧縮 |
| 文字の命令 `Tj` `TJ` `'` `"`、行送り `Td` `TD` `T*` `Tm`、フォントの指定 `Tf` | 壊れた相互参照の修復（修復しない） |
| フォントの `ToUnicode`（`bfchar`・`bfrange`・配列の形・`codespacerange`。サロゲートペアを含む） | `ToUnicode` の無い複合フォント（CID）を使う文字 |
| `ToUnicode` の無い単純フォント（WinAnsi 相当の 1 バイト文字） | OCR（画像の文字は読まない） |

- **場所**: ページの順に `ページ001` `ページ002` …（`ページ{0:D3}`）。場所の名前は Word のページと同じ形。
- **行**: 縦に動く `Td` `TD`、`T*`、`'` `"`、縦の位置が変わる `Tm`、テキストの終わり `ET` で行を分ける。横だけ動くときは行を分けず、半角の文字どうしなら空白でつなぐ。`TJ` の詰めの数値が `-250` 以下で、前後の文字がどちらも半角のときだけ半角の空白を 1 つ入れる。
- **画像のインラインデータ**（`BI` … `ID` … `EI`）は読み飛ばす。
- 文字の位置・向き・列の並び（段組み）は見ない。ページの中の文字は、ファイルに書かれた順に並ぶ。

## 読み取りの上限

細工した PDF で固まったり、メモリを使い切ったりしないよう、すべて上限を設ける。超えたら失敗にする（`PDF` で始まるメッセージの例外）。

| 上限 | 値 | 超えたとき |
|---|---|---|
| 元のファイルの大きさ | 100MB（コピーの前に確かめる） | `ファイルサイズが大きすぎるため更新できません。` |
| 解凍後の大きさの合計 | 100MB | `PDFの解凍後の大きさが上限を超えるため読めません。` |
| オブジェクトの数 | 1,000,000 | `PDFのオブジェクトの数が上限を超えるため読めません。` |
| 入れ子の深さ（配列・辞書・間接参照・ページツリー） | 64 | `PDFの入れ子が深すぎるため読めません。` など |
| ページ数 | 10,000 | `PDFのページ数が上限を超えるため読めません。` |

参照の循環（ページツリー・間接参照・古い相互参照のつながり）と、ファイルの外を指す相互参照の位置は、例外にする。

## 読めない PDF

読めないときは、そのファイルだけが取り込みの失敗になり、インデックス作成は続く。画面・取り込み一覧のメッセージは `PDF` で始まる短い文言（[エラーメッセージ一覧](errors.md)）。`readPdfPages` は、`PDF` で始まらない例外を `PDFが壊れているため読めません。` に言い換える（内部の例外の文言を出さない）。

## 検索・開く

- 種類のチップ「PDF」（`setting.config` の `fileKinds` の値 `pdf`）で、PDF だけを絞れる。保存済みの `fileKinds` が一部の種類だけのときは、PDF は選ばれていない状態から始まる（設定ファイルの形は変えない）。
- 結果の見出しのアイコンは `PDF`（`getAppKind`）。場所は `ページN`。
- 検索結果から開くと、既定のアプリで開く（ページへは移動しない）。ステータスは `開きました：<パス>`（[検索結果からファイルを開く](../gui/open-file.md)）。
