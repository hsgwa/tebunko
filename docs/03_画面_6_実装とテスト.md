別スレッドの扱い：

- 検索と TSV の件数取得は Runspace で実行する。検索結果はスレッド間で共有するキュー（`ConcurrentQueue`）に入れ、画面の `DispatcherTimer`（0.1 秒間隔）で取り出して表に加える。中止はフラグで伝える。
- 変換のプロセスは `Start-Process -PassThru`（ウィンドウなし）で起動し、`DispatcherTimer`（1 秒間隔）で `HasExited` と変換一覧を確認する（3.3）。終了後は `ExitCode` で表示を分ける（3.4）。起動時と開始時は、`Win32_Process` のコマンドラインから実行中の変換を探し、見つかればそのプロセスを監視する（3.1）。
- 多重起動は、ツールの配置フォルダごとの名前付き Mutex で防ぐ。

注意（PowerShell 5.1）：`System.Collections.Generic.List[object]` を `@()` で配列にすると例外（Argument types do not match）になる。結果のリストは `List[psobject]` にするか `.ToArray()` で返す。

## 13. 既存スクリプトへの影響と段階

| 段階 | 内容 | 既存スクリプトへの影響 |
|---|---|---|
| 第 1 段階（**実装済み**） | 3 タブ構成、変換の起動と状態表示、画面内での検索（結果の表・強調・並べ替え・絞り込み・選択行の詳細・元のファイルを開く・コピー・ファイル出力・履歴・正規表現の切り替え）、変換の進み具合、Office 強制終了 | `grep.ps1`・`kill_process.ps1` の処理を `common.ps1` の関数に切り出した（動作は変えていない。両スクリプトは第 2 段階で削除した） |

| 第 3 段階（検討） | Word・PowerPoint の該当ページ・スライドへの移動（既定以外のインデックスフォルダの結果を開くことは、`元のフォルダ.txt` と置き換えで対応済み。4.5.1・4.5.2） | Word・PowerPoint の COM 操作を追加する |

## 15. 既知の制約

確度: ◎ = 動作確認済み、○ = コード上明らか、△ = 推定。

| # | 内容 | 確度 |
|---|---|---|
| 1 | ~~`1_変換.bat` を直接実行した場合、画面からは「変換中」と判定できない。画面から変換を起動すると二重起動になりうる~~ 解消：実行中の変換を `Win32_Process` のコマンドラインで探し、見つかればその進み具合を表示する（3.1） | – |
| 2 | ~~`1_変換.bat` は最後に `pause` するため、コンソールを閉じるまで「変換中」の表示が続く~~ 解消：変換はウィンドウなしで実行し、`pause` しない（`1_変換.bat` は廃止した） | – |
| 3 | 元のファイルのパスは、変換時に記録した変換対象フォルダから組み立てる。変換後に元のフォルダを移動・名前変更した場合は、開くときにフォルダを選び直す必要がある（選んだフォルダは置き換えとして記録し、同じフォルダの下は次から聞かない。4.5.2） | ○ |
| 4 | `元のフォルダ.txt` の無い古いインデックス（変換を 1 回実行すると作られる）を別の場所にコピーした場合は、元の場所が分からないため、開くときにフォルダを選ぶ必要がある | ○ |
| 5 | バックグラウンドの判定は `MainWindowHandle` による。画面に表示中でも、すべてのウィンドウを閉じた直後などはバックグラウンドと判定される（5.1） | △ |
| 6 | フォルダ選択ダイアログは Windows 標準のエクスプローラー形式（`IFileOpenDialog` のフォルダ選択モード）で、パスを貼り付けて選べる。この部品が使えない環境では .NET Framework 標準の `FolderBrowserDialog`（ツリー形式。パスを入力できない）になる | ○ |
| 7 | TSV が非常に多い場合、件数を数え終わるまで状態表示が `確認中…` になる | △ |
