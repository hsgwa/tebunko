## 1. 何が起きているのか

AppLocker・WDAC（アプリケーション制御）を強制した PC では、**管理者が許可していない PowerShell スクリプトは「制限言語モード（ConstrainedLanguage）」で動く**。この状態では次が使えない。

- `Add-Type`（WPF。いつもの画面の土台）
- PowerShell class
- COM（Excel・Word・PowerPoint の自動操作）
- コア以外の .NET の型

tebunko はこれを起動時に調べ（`scripts/tebunko_grep/start.ps1`）、いつもの画面を開けないときは**制限モード**（同じコンソールで動くコンソール版）で起動して、理由と頼み方を表示する。

```
制限モードで起動します。
  理由: この PC では PowerShell が制限言語モード（ConstrainedLanguage）で動いています。
  使えない機能: 画面（ウィンドウ）と、Excel・.xls/.doc/.ppt・パスワード付きのファイルの取り込み
  インデックスの作成: Word・PowerPoint（.docx .docm .pptx .pptm）だけ取り込めます。ほかはいつもの画面が使える PC で取り込んでください。
  いつもの画面を使うには: 管理者にツールのフォルダの実行許可を依頼してください。
```

**制限言語モードを回避する抜け道（署名の偽装、許可された COM の悪用、mshta など）は使っていない。** 制限モードは、制限言語モードで使える機能（標準のコマンドレット・コアの型・Windows に付いている `tar.exe`）だけで作ってある。

## 2. どちらで使わせるかを決める

| | いつもの画面（許可する） | 制限モード（許可しない） |
|---|---|---|
| 画面 | ウィンドウ（一覧・プレビュー） | コンソール（メニューと番号） |
| 取り込めるファイル | Excel・Word・PowerPoint の新形式と旧形式（.xls / .doc / .ppt）、パスワード付きも | 新形式（.docx / .docm / .pptx / .pptm / .xlsx / .xlsm）だけ |
| 検索 | できる | できる（同じインデックス・同じ結果） |
| 検索結果 | 画面の一覧・プレビュー | Excel のブックで開く（Excel が無い PC はコンソールに一覧） |
| 元のファイルを開く | 通常・読み取り専用・新規 | 関連付けのアプリで開く |
| 必要な許可 | ツールのフォルダの実行許可 | 不要（そのまま動く） |

**判断の目安**

- 旧形式（.xls / .doc / .ppt）やパスワード付きのファイルを探したい → **許可する**。制限モードでは取り込めない。
- 新形式だけでよい → 許可しなくてよい。制限モードのままインデックスの作成から検索までできる。
- インデックスを 1 か所（許可された PC・サーバー）で作り、ほかの PC は検索だけ → 許可しなくてよい。インデックス（`work\index`）を共有フォルダに置けば、制限モードの PC からも検索できる。

## 3. 許可するときの設定

tebunko は**署名のない PowerShell スクリプト**（`.ps1`・`.psm1` は無し・`.xaml`・`.bat`）だけでできている。実行ファイル（`.exe`・`.dll`）も、他者が作ったライブラリも含まない（[04_安全性.md](04_安全性.md)）。そのため許可は**パス規則**で行う。

### 3.1 AppLocker

「スクリプト」の規則に、ツールを置いたフォルダのパス規則を足す。

| 項目 | 値の例 |
|---|---|
| 規則の種類 | パス |
| パス | `%PROGRAMFILES%\tebunko\scripts\*` と `%PROGRAMFILES%\tebunko\tebunko_grep.bat`（配布先に合わせる。共有フォルダなら `\\server\share\tebunko\...`） |
| 対象 | スクリプト（`.ps1` `.bat` `.cmd`） |
| ユーザー | 利用者のグループ |

- **許可するのは `scripts\` と起動用の `tebunko_grep.bat` だけにし、そこは利用者が書き込めないようにする。** 書き込めると、許可したフォルダに別のスクリプトを置かれてしまう。
- **`work\`（インデックス・ログの置き場所）は許可しなくてよい。** ツールのフォルダの下にあるが、スクリプトは入らない（TSV とログだけ）。利用者が書き込めるままにしておく。
  - 配布物のフォルダをまるごと読み取り専用にする運用にはできない。`work\` は tebunko が作り、インデックス作成のたびに書き込む。
- 発行元規則（署名）を使う場合は、社内の証明書で `.ps1`・`.bat` に署名してから配布する。tebunko は署名を含めずに配布しているため、署名は導入側で行う。署名した後は、実行ポリシーを `AllSigned` にしてもそのまま動く。

### 3.2 WDAC（Windows Defender アプリケーション制御）

WDAC でも同じく、**パス規則（`FilePath`）か署名規則**でツールのフォルダを許可する。

- `New-CIPolicyRule -FilePathRule "C:\Program Files\tebunko\scripts\*"` で作った規則をポリシーに足す（`Merge-CIPolicy`）。起動用の `tebunko_grep.bat` も同じように足す。
- パス規則を使うポリシーは、`Enabled:UserWriteablePaths` を有効にしない限り、**利用者が書き込めるフォルダのパス規則を無視する**。`scripts\` と `tebunko_grep.bat` は利用者が書き込めない場所に置く（`work\` は書き込めてよい。3.1）。
- 署名規則を使う場合は、社内の証明書で署名し、その証明書を `New-CIPolicyRule -Level Publisher` で許可する。

本リポジトリの CI では、実際に WDAC のポリシーを当てた Windows で制限モードの部品が動くことを毎回確かめている（`.github/workflows/clm.yml`。詳細は [00_共通_3_テスト.md](00_共通_3_テスト.md) の「CI」）。

### 3.3 実行ポリシー（グループポリシー）

- tebunko の `tebunko_grep.bat` は `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File ...` の形で起動する。**グループポリシーで実行ポリシーを決めている場合、コマンドラインの `-ExecutionPolicy` は無視される**（ポリシーが優先する）。
- `AllSigned` を強制している場合は、3.1 のとおり社内の証明書で署名してから配布する。署名が無いと、いつもの画面・制限モードのどちらも起動しない。このとき bat は `start_failed.txt`（対処の手順）と `Get-ExecutionPolicy -List` の結果をコンソールに出して止まる。
- `RemoteSigned` の場合は、次の 3.4 の Mark-of-the-Web を外せばそのまま動く（bat が起動時に `scripts\` のファイルの印を外す）。
- `Restricted` を強制している場合も動かない。`RemoteSigned` 以上にするか、署名する。

### 3.4 共有フォルダ（UNC）とゾーン

- インターネットから落とした zip と、**イントラネットゾーンではない共有フォルダ**のファイルには Mark-of-the-Web が付く。`RemoteSigned` では、これが付いたスクリプトは署名が無いと実行できない。
- 対処はどちらか。
  - zip を展開する前に、zip のプロパティで［ブロックの解除］にチェックを入れる。
  - 共有フォルダを「ローカル イントラネット」ゾーンに登録する（グループポリシーの「サイトとゾーンの割り当て一覧」）。
- tebunko は、展開したフォルダのファイルに付いた Mark-of-the-Web を起動時に自分で外す（[03_画面_5_共通仕様.md 10.1](03_画面_5_共通仕様.md#101-配布と実行ポリシーmark-of-the-web)）。外せないときは、上のどちらかを行う。

## 4. 制限モードのまま使わせるときに確かめること

| 確かめること | 方法 |
|---|---|
| 制限モードで起動するか | `tebunko_grep.bat` を実行し、「制限モードで起動します」と出ること |
| `tar.exe` を呼べるか | `%windir%\System32\tar.exe` が WDAC・AppLocker で止められていないこと（検索結果のブックの作成と、ファイルの取り込みに使う） |
| Excel があるか | 検索結果はブックで開く。無い場合はコンソールに一覧で出る（動作はする） |
| `work\` に書き込めるか | インデックスと設定の保存に要る。書き込めないときは起動時に「注意」として表示する |
| `%TEMP%` に書き込めるか | 検索結果のブックと、取り込みの作業フォルダに使う |

確認だけを行うコマンド（終了コードで分かる。`10` = いつもの画面を開ける、`11` = 制限モードで起動する）。

```
powershell -NoProfile -ExecutionPolicy RemoteSigned -File <ツールのフォルダ>\scripts\tebunko_grep\start.ps1 -CheckOnly
echo %ERRORLEVEL%
```

いまの言語モードだけを見るなら次のとおり。

```
powershell -NoProfile -Command "$ExecutionContext.SessionState.LanguageMode"
```

## 5. よくある質問

**Q. 制限モードは、アプリケーション制御の抜け道ではないのか。**
A. 違う。制限言語モードで**許可されている機能だけ**で作ってある。使う外部プログラムは Windows に付属する `cmd.exe` と `tar.exe` の 2 つで、どちらもアプリケーション制御の規則で許可された実行ファイルとして動く（[04_安全性.md](04_安全性.md) の 2.3）。署名の偽装・許可された COM の悪用・`mshta` などは使っていない。

**Q. 制限モードで作ったインデックスを、いつもの画面が使える PC で使えるか。**
A. 使える。取り込み一覧・インデックスの形式は同じ。ただし Excel のセルは、制限モードでは表示形式を自前で当てるため一部の表示が Excel と違う（[05_制限モード.md](05_制限モード.md) の 5.6）。そのため制限モードで取り込んだ行には印（抽出版の `R`）を付けてあり、**いつもの画面が使える PC でインデックスを作成すると、その行だけを Excel の表示どおりに取り込み直す**。

**Q. 利用者が勝手にインデックスを作って、共有フォルダに負荷がかからないか。**
A. インデックスの作成はファイルを読むだけで、元のファイルは書き換えない。制限モードでは Office を起動しないため、Office のライセンスもプロセスも消費しない。

**Q. 通信するか。**
A. しない。tebunko は通信・常駐・レジストリの変更・管理者権限の要求のいずれも行わない（[04_安全性.md](04_安全性.md)）。
