## 3. ［1 インデックス管理］タブ

インデックスを **作成・一覧・編集・削除** し、中身（TSV）の変換を実行するタブ。
図は「前回の変換で失敗があり、変換を実行中」の状態。

![［1 インデックス管理］タブ](images/画面_インデックス管理タブ.drawio.png)

| No. | 部品 | 仕様 |
|---|---|---|
| 1 | インデックス一覧 | 見出しは `インデックス一覧（チェックを付けたインデックスを変換します）`。1 行 1 インデックス（1 フォルダ）。列は「変換」（チェック）・「インデックス名」・「元のフォルダ」・「フォルダの状態」・「ファイル」・「最終変換」（3.1）。**チェックを付けたインデックスだけを変換する**（チェックを外したインデックスは、一覧にも `work\index` にも残したまま変換しない）。一覧が空なら `インデックスがありません。［新規作成…］で、Office ファイルのあるフォルダを指定してください。`。並びは `targetFolders` の順で、検索対象のツリー（4.10）もこの順に並ぶ |
| 2 | ［新規作成…］ | 新規作成のダイアログ（3.2）を開き、決めた内容でインデックスを 1 件作る。一覧へのフォルダのドラッグ＆ドロップでも作れる（このときインデックス名はフォルダ名から自動で決める）。作成するだけで変換はせず、ステータスに `インデックス [<名前>] を作成しました。［変換を開始］を押すと中身を変換します` と表示する（フォルダが見つからない場合は `インデックス [<名前>] を作成しましたが、フォルダが見つかりません：<パス>`）。同じフォルダ（書き方の違い・大文字小文字を含む）のインデックスは二重に作らない |
| 3 | ［編集…］ | 選択中のインデックスの**名前**と**元のフォルダの場所**を変える（3.2。行のダブルクリックでも開く）。変えても**インデックスは作り直さない**。変更したらステータスに `インデックスを変更しました（名前 [<旧>] → [<新>] / 場所 <旧> → <新>）` と表示する |
| 9 | ［作り直す…］ | No.3 と No.4 の間に置く。選択中のインデックスを**一から作り直す**（TSV を削除してから、フォルダの中の Office ファイルをすべて変換し直す）。差分変換では変換し直さない次の場合に使う: 元ファイルの更新日時・サイズが変わらないまま中身が変わった（[01_変換_7 の 7.1 #4](01_変換_7_出力TSVと既知の問題.md#71-共通)）／TSV の中身が壊れた（0 バイトの TSV は変換側が見つけて作り直すが、中身の書き換えまでは分からない）。`インデックス [<名前>] を作り直します。元のフォルダ：<パス> 変換した TSV（work\index\<名前>）を削除し、フォルダの中の Office ファイルをすべて変換し直します（件数によっては時間がかかります）。ふだんは、更新されたファイルだけを変換する［変換を開始］で足ります。元のファイルの更新日時が変わらないまま中身が変わった場合などに使ってください。［変換］のチェックが外れている場合は付けます。作り直しますか？` と確認する（既定のボタンは［いいえ］）。［はい］で `removeIndex`（No.4 と同じ。別スレッドで行い、その間はステータスに `…の TSV を削除しています…` と出す）を行い、［変換］にチェックを付けてから変換を開始する。ステータスに `インデックス [<名前>] を作り直します（変換を開始しました）` と表示する（変換を始めるときの確認でキャンセルした場合は `インデックス [<名前>] の TSV を削除しました。［変換を開始］を押すと作り直します`）。まだ変換していない（インデックス名が無い）場合は `このインデックスはまだ変換していません。［変換を開始］で作成してください` と表示して何もしない。元のフォルダが見つからない場合は、消しただけの状態になるため `元のフォルダが見つからないため、インデックス [<名前>] を作り直せません。…` と出して何もしない |
| 4 | ［削除］ | 選択中のインデックスを削除する（Delete キーでも同じ）。`インデックス [<名前>] を削除します。元のフォルダ：<パス> 変換した TSV（work\index\<名前>）と変換一覧の記録を削除します。元のフォルダと Office ファイルは削除しません。一時的に変換しないだけなら、削除せずに［変換］のチェックを外してください。削除しますか？` と確認する（既定のボタンは［いいえ］）。［はい］で一覧からすぐ消し、`work\index\<名前>` と変換一覧の記録の削除（`removeIndex`）は**別スレッド**で行う（数万フォルダでは数十秒かかることがあり、画面のスレッドで行うと「応答なし」になるため）。削除の間はステータスに `インデックス [<名前>] の TSV を削除しています…（件数によっては少し時間がかかります）` と出し、インデックスの操作・変換の開始はできないようにする。終わったらステータスに `インデックス [<名前>] を削除しました` と表示する |
| 5 | インデックスの状態 | すべてのインデックスの合計。`変換済み N ファイル（TSV M 件 ・ 最終変換 M/d H:mm）`。インデックスが無いときは `まだインデックスがありません。`。中断があれば次の行に表示する（6.1）。失敗は No.8 の一覧に表示する |
| 6 | 注意書き・実行ボタン | 注意書きは `変換中も検索できます。途中でやめるときは［中止］を押してください（次回、続きから再開できます）。`。ボタンは状態に応じて表示を変える（3.3）。押すと `office_to_tsv.ps1` をウィンドウなしで起動し、進み具合を表示する（3.5） |
| 7 | タブ見出し | 変換の失敗が残っているとき `⚠` を付ける |
| 8 | 変換に失敗したファイル | 変換一覧に状態が `失敗` の行があるときだけ表示する。見出しは `⚠ 変換に失敗したファイル N 件`。列は「ファイル」（相対パス）・「失敗の原因」（変換一覧のエラー列。[01_変換.md 4.7](01_変換_6_共通処理とアプリ管理.md#47-失敗の原因describeconverterror)）・「日時」。変換日時の新しい順に並べ、高さを超えたらスクロールする。行をダブルクリックすると、元のファイルをエクスプローラーで選択した状態で開く（ファイルが無ければフォルダを開き、ステータスに表示する）。変換中も、失敗が増えるたびに更新する。変換が終わったとき失敗があれば、進み具合の下に `失敗したファイルと原因は「変換に失敗したファイル」の一覧で確認できます。` と表示する |

- インデックスの作成・編集・削除・チェックの変更は、その場で `setting.config`（`targetFolders`）に保存する（`writeTargetFolders`。チェックなしは `enabled` が `false`）。保存の操作は無い。
- **変換中は作成・編集・作り直し・削除をしない**。［新規作成…］［編集…］［作り直す…］［削除］は無効にし、操作しようとした場合は `変換中はインデックスを<作成／編集／作り直し／削除>できません。変換が終わるまでお待ちください（［中止］で止められます）。` と出す。変換側がインデックスのフォルダと変換一覧を使っているため。
- ［編集…］［作り直す…］［削除］は、一覧で 1 件選んでいるときだけ有効にする。

**インデックス名と場所は分けて持つ**（`targetFolders` の `name` と `path`）。`name` が `work\index` 直下のフォルダ名になり、インデックスの同一性を表す。`path` を書き換えても `name` は変わらないため、フォルダを移してもインデックスを作り直さない（[01_変換_5](01_変換_5_変換対象の決定.md#変換対象フォルダとインデックス名)）。
画面では**作成した時点で名前を決めて保存する**（新規作成のダイアログの既定値は `newIndexName`）。名前の無い設定（以前の版から移した直後）を読み込んだときは、`assignIndexNames` で名前を割り当てて保存してから一覧に出す。

#### 名前を変えたときの処理（`renameIndex`）

名前を変えても**インデックスは作り直さない**。次の順に、名前だけを付け替える。

1. `work\index\<旧名>` を `work\index\<新名>` に改名する（長いパスの TSV があっても扱えるよう `\\?\` 付きで操作する）。移動先が既にあれば例外にして何もしない。大文字・小文字だけを変える場合は一時名を経由する
2. 変換一覧（`work/変換一覧.tsv`）の `変換対象フォルダ` の行のインデックス名と、各行の相対パスの先頭（`<旧名>\…` → `<新名>\…`）を書き換える（`renameStatusIndexName`。行の順序と内容はそのまま保ち、一時ファイルに書いてから置き換える）
3. `setting.config` の `targetFolders[].name` を保存し、`work\index\元のフォルダ.txt` を書き直す（`updateIndexSourceFile`）

#### 削除したときの処理（`removeIndex`）

1. `work\index\<名前>` を中身ごと削除する（`\\?\` 付き）
2. 変換一覧から、そのインデックスの `変換対象フォルダ` の行と各ファイルの行を取り除く（`removeStatusIndexName`）
3. `setting.config` から外して保存し、`元のフォルダ.txt` を書き直す

変換側の `removeDroppedFolders`（[01_変換_5](01_変換_5_変換対象の決定.md#変換対象フォルダとインデックス名)）は、画面を通さずに設定を書き換えた場合の後始末として残す。画面から削除した場合は、その場で消えているため何もしない。

### 3.2.1 フォルダ選択ダイアログ（［参照…］）

`config_gui_folder_select.xaml`。**エクスプローラーと同じ感覚で、フォルダの中身を見ながら目的のフォルダまでたどれる**ようにする。

Windows 標準のフォルダ選択（WinForms の `FolderBrowserDialog`）はツリーだけでフォルダの中身が見えず、「このフォルダで合っているか」を確かめられない。エクスプローラー形式の標準ダイアログ（COM の `IFileOpenDialog`）は呼び出しに実行時コンパイルが要るため使えない（[12.2](03_画面_6_実装とテスト.md#122-実行時コンパイルcscexeを使わない)）。そのため、画面として作る。

［参照…］（[3.2](#32-新規作成編集のダイアログ)）と、元のファイルのフォルダを選んでもらう場面（[4.5.2](03_画面_2_検索タブ_1_元のファイルを開く.md#452-元のファイルが見つからないとき元のフォルダを設定する)）で共通に使う（`selectFolder`）。

| 部品 | 仕様 |
|---|---|
| 説明（最上段） | 呼び出し元が渡す文言。新規作成・編集は `インデックスにする、Office ファイルのあるフォルダを選んでください` |
| ［←］［→］［↑］ | 履歴を戻る・進む、1 つ上のフォルダへ。マウスのサイドボタン（戻る・進む）でもたどれる。たどれないときは押せない（ドライブ直下・共有フォルダ直下より上へは行かない） |
| アドレスバー | 今のフォルダのパス。入力・貼り付けて `Enter` で移動する。前後の空白・`"`・末尾の `\` は取り除く（`normalizeFolderPath`。エクスプローラーの「パスのコピー」や `\\server\share` をそのまま貼れる） |
| ツリー（左） | `よく使う場所`（デスクトップ・ドキュメント・ダウンロードのうち、あるもの）と `PC`（使えるドライブ。ネットワークドライブは割り当て先 `\\server\share` を名前に出す）。▷ で下のフォルダを開き、開いたときに 1 段だけ読み込む |
| 一覧（右） | 今のフォルダの中身。フォルダが先、それぞれ名前順。列は `名前`・`種類`・`更新日時`。**選べるのはフォルダだけで、ファイルは薄く出す**（Office ファイルは緑にし、目的のフォルダかどうかを確かめられるようにする）。ダブルクリック・`Enter` でそのフォルダへ移動する |
| 件数（一覧の下） | `フォルダー N 個 ・ Office ファイル M 個`。打ち切った場合は `（中身が多いため、先頭だけを表示しています）` を付ける |
| ［フォルダー：］ | 選ぶフォルダのパス。一覧でフォルダを選ぶと入り、選んでいなければ今のフォルダ。入力・貼り付け・フォルダのドラッグ＆ドロップもできる |
| ［選択］ | ［フォルダー：］のパスを返す（`Enter`） |
| ［キャンセル］ | 何も返さない（`Esc`） |

**キーボード・マウスの操作**（エクスプローラーに合わせる）:

| 操作 | 内容 |
|---|---|
| `Alt+←` / `Alt+→` / マウスのサイドボタン | 戻る・進む |
| `Alt+↑` / `BackSpace` | 1 つ上のフォルダへ（`BackSpace` は入力欄では文字を消すため、入力欄以外にいるときだけ） |
| `F5` / `Ctrl+R` | 今のフォルダとツリーの下を読み直す |
| `F4` / `Alt+D` / `Ctrl+L` | アドレスバーへ移り、今のパスを選んだ状態にする |
| `Enter`（一覧） | 選んでいるフォルダへ移動する（ダブルクリックと同じ） |
| `Enter`（それ以外） | ［選択］ |
| `Esc` | ［キャンセル］ |

**左のツリーの追随**：エクスプローラーと同じく、**移動しただけでは途中のフォルダを勝手に開かない**。すでに開いてあるところにそのフォルダがあれば選び、1 つ上のフォルダが開いてあれば、そこだけ開いて選ぶ（右の一覧で下りると 1 段ずつ開く）。深いパスを貼り付けた場合など、ツリーに出ていないフォルダのときは選択を外すだけにする。

- **最初に開くフォルダ**：呼び出し元が渡したフォルダ（［参照…］は今の入力値）。無ければその上の、今もあるフォルダ →「よく使う場所」→ ドライブ の順に試す。
- **開けないフォルダ**（権限が無い・切れているネットワークドライブ・消えたフォルダ）は移動せず、下に赤字で `「<パス>」を開けません。<理由>` と出す。［選択］のときは `「<パス>」は見つかりません。一覧から選ぶか、パスを確かめてください。`。
- **隠し・システムのフォルダとファイルは出さない**（エクスプローラーの既定と同じ）。
- 中身の多いフォルダでも待たせないよう、一覧は 2000 件で打ち切る（`getFolderEntries` の `limit`）。

### 3.3 実行ボタンの表示

| 状態（6.1） | ボタン |
|---|---|
| 未作成・通常 | ［変換を開始］ |
| 中断中 | ［続きから再開（残り N 件）］ |
| 失敗あり | ［変換を開始］（中断中なら［続きから再開（残り N 件）］）。注意書きの前に `前回失敗したファイルがあります。変換を始めるときに、再変換するかを選べます。` を付ける。押すと次の確認を出す（既定のボタンは［いいえ］）：`前回変換に失敗し、その後更新されていないファイルが N 件あります（パスワード付きなど）。これらも再変換しますか？（「いいえ」の場合はスキップして、新しいファイル・更新されたファイルだけを変換します）`。［はい］は `-RetryFailed` を付けて起動し、［いいえ］は失敗分をスキップして起動する。［キャンセル］は起動しない |
| 変換中 | 無効。表示は `変換中…`。進み具合と［中止］を表示する（3.5）。［新規作成…］［編集…］［削除］も無効にする |
| チェックを付けた、存在するフォルダが無い | 無効。注意書きを `インデックスを作成して、チェックを付けてください。` にする |

- 変換は `powershell -NoProfile -ExecutionPolicy RemoteSigned -WindowStyle Hidden -File scripts\office_to_tsv.ps1 [-RetryFailed]` で起動する。ウィンドウは出さない（コンソールでの確認・`pause` は無い）。`Bypass` は使わない（Mark-of-the-Web は起動時に消してある。[03_画面_5_共通仕様.md 10.1](03_画面_5_共通仕様.md#101-配布と実行ポリシーmark-of-the-web)）。
- 「変換中」は、この画面から起動した変換のプロセスが終了するまでとする。変換の二重起動を防ぐ。
  - 画面の起動時と［変換を開始］を押したときは、このツールの `scripts\office_to_tsv.ps1` をコマンドラインに含む `powershell.exe` が動いていないかも調べる（`Win32_Process`）。動いていれば新たに起動せず、そのプロセスの進み具合を表示する。起動時に見つかった場合は［1 インデックス管理］タブを開く。

### 3.4 インデックス一覧を変更したとき

確認は出さずにそのまま保存する。
変換一覧（`work/変換一覧.tsv`）の 1 行目には変換対象フォルダを記録しており、変換時に今のフォルダと異なれば変換一覧を作り直す（[01_変換.md 4.2 節](01_変換_4_メインフローと変換一覧.md#42-変換一覧と変換対象の決定差分中断再試行)）。
そのため、変更前のフォルダの相対パスのまま新しいフォルダを処理することはない。

### 3.5 変換の進み具合

変換はウィンドウなしで実行するため、画面は**変換が書く進み具合の 1 行**（`work/変換進捗.txt`。`readConvertProgress`）を 1 秒ごとに読んで表示する。
変換側の書き込みを妨げないよう共有を許して読む。

| 状況 | 判定（進み具合の段階） | 表示 |
|---|---|---|
| 変換対象の検索中 | `準備` | 動き続けるバー。`変換対象のファイルを確認しています…`。下に、変換が今していること（`[<インデックス名>] のOfficeファイルを探しています… <パス>`・`変換済みのインデックスを確認しています…`・`変換一覧を書き出しています…`） |
| 変換の開始前 | `変換` で処理済みが 0 | 動き続けるバー。`N 件のファイルを変換します`、`変換中のファイル：<相対パス>` |
| 変換中 | `変換` で処理済みが 1 件以上 | バー（処理済み ÷（処理済み＋残り））、`変換中… 14 / 31 件（失敗 1 件）`、`残り約 N 分`（最初の 1 件が終わってからの速さで計算）、`変換中のファイル：<相対パス>` |
| 後片付け中 | `仕上げ` | 動き続けるバー。`変換を終えています…`、`Officeアプリを終了しています…` / `変換一覧を書き直しています…` |
| 終わった | プロセスが終了した | 終了コードに応じて表示する（3.6）。状態・件数を読み直す |

- タスクバーのアイコンにも進み具合を表示する（失敗があれば黄色）。**変換が終わったとき、進み具合とステータスで知らせる**（以前はタスクバーのボタンを光らせていたが、P/Invoke（`FlashWindowEx`）を無くすため廃止した）。前面には割り込まない。
- **変換一覧（`work/変換一覧.tsv`）は毎秒読まない**。数万行になると 1 回の読み直しに数秒かかり（5 万行で約 5.8 秒）、1 秒ごとに読むと画面が固まる（「応答なし」になる）。進み具合は変換側が数えて 1 行に書く（[01_変換_4](01_変換_4_メインフローと変換一覧.md#41-メインフロー)）。
- 「処理済み」は変換側が数えた件数（今回の実行で変換・失敗したファイル）。前回失敗したファイルを再変換する場合（確認で［はい］）も、その分は最初から件数に入る。

### 3.6 中止・終了・ログ

- 変換中は、進み具合の右に［中止］を表示する。押すと `変換を中止しますか？変換中のファイルが終わったところで止まります。次回は続きから再開できます。` と確認する（既定のボタンは［いいえ］）。［はい］で `work/変換中止要求`（`$stopRequestFile`）を作る。変換側は変換中のファイルが終わったところで止まり、終了コード 2 で終わる。終わるまでは `中止しています…（変換中のファイルが終わるまでお待ちください）` と表示する。
- プロセスが終わったら、終了コードに応じて次のように表示する。

| 終了コード | 表示 |
|---|---|
| 0 | `変換が終わりました（成功 N 件 / 失敗 M 件）`。失敗があれば `失敗したファイルと原因は「変換に失敗したファイル」の一覧で確認できます。` を加える。変換したファイルが無ければ `変換が必要なファイルはありませんでした` |
| 2（中止した） | `変換を中止しました（成功 N 件 / 失敗 M 件 / 残り K 件）`、`次回は続きから再開できます。` |
| 1（続けられないエラー。変換対象フォルダが無い など） | `work/変換エラー.txt`（`$convertErrorFile`）を読み、`変換できませんでした` とそのメッセージを表示する。同じ内容をエラーのダイアログでも出す |

- プロセスが終わると［ログを開く］を表示する。変換のログ `work/変換ログ.txt`（`$convertLogFile`。変換側の実行記録）を開く。
- 変換中にウィンドウを閉じようとすると、次の確認を出す（既定のボタンは［キャンセル］）：`変換中です。［はい］変換を中止してから閉じる（変換中のファイルが終わったところで止まります）［いいえ］変換を続けたまま閉じる（もう一度開くと進み具合を表示します）［キャンセル］閉じない`。［はい］は中止の要求ファイルを作ってから閉じる。［いいえ］は変換を続けたまま閉じ、次に画面を開くと実行中の変換を見つけて進み具合を表示する（3.3）。
