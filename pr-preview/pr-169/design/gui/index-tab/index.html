    ツールヒントは、状態の札（ステータス・高速検索のバッジ）と、「ステータス」「高速検索」の列見出しにだけ付ける（文は「です・ます」で書く）。［＋ フォルダを追加］［アクション ▾］とそのメニューの項目・行の［更新］［中止］・全選択のチェックには付けない（見た目と名前で分かるため）。一覧の「名前」「パス」の列と、詳細の名前・フォルダパス・更新中のファイル名は、「…」で切れているときだけ全文をツールヒントで見せる（shared/ui/trimmed_tooltip.ps1 の addTrimmedToolTip。一覧は行の Loaded で付ける）。切れていなければ出さない。「ステータス」の列見出しには、状態の名前と意味を並べた説明（getIndexStatusHelpText）を、「高速検索」の列見出しには、インデックス（高速検索用）が Windows Search にどこまで反映されたかの説明を出す。

    「ファイル」「最終更新」は取り込み一覧（work/ingest_status.tsv）の集計で、状態を読み直すたび（起動時・ウィンドウがアクティブになったとき・インデックス作成中は 1 秒ごと）に更新する。「高速検索」は、一覧の読み込み時・ウィンドウがアクティブになったとき（前回の確認から 60 秒以上たっていれば）・インデックス作成が終わったとき・追加／編集／削除／インポートの後に確かめ直す。反映待ち・反映中 N% の行が 1 つでもある間は、5 分ごとのタイマーでも確かめ直す（インデックス作成中は確かめない）。

    名前 画面では 名前 とだけ書き、work\content_index 直下のフォルダ名になることは書かない（利用者が決めるのは検索対象の一覧と検索結果に出る名前のため）。入力欄の下は 検索対象の一覧と検索結果に、この名前が出ます。\ / : * ? " < > | は使えません。。追加では、フォルダを指定すると newIndexName の名前を自動で入れる（利用者が名前を変えた後は上書きしない）。編集では今の名前を初期値にする

    名前を変えたときの処理（renameIndex）¶

    flowchart TD
    A["work\content_index\旧名→新名 に改名<br>（\\?\ 付き）"] --> B["取り込み一覧の名前・相対パスを書き換え<br>（renameStatusIndexName）"]
    B --> C["targetFolders[].name を保存・source_folder.txt を書き直す<br>（updateIndexSourceFile）"]
    C --> D["旧名・新名の下の searchExcludes を消す<br>（removeSearchExcludesUnder）"]

    名前を変えてもインデックスは作り直さない。次の順に、名前だけを付け替える。

    1. work\content_index\<旧名> を work\content_index\<新名> に改名する（長いパスの本文インデックスのファイル・TSV があっても扱えるよう \\?\ 付きで操作する）。移動先が既にあれば例外にして何もしない。大文字・小文字だけを変える場合は一時名を経由する
    2. 取り込み一覧（work/ingest_status.tsv）の クロール対象フォルダ の行のインデックス名と、各行の相対パスの先頭（<旧名>\… → <新名>\…）を書き換える（renameStatusIndexName。行の順序と内容はそのまま保ち、一時ファイルに書いてから置き換える）
    3. setting.config の targetFolders[].name を保存し、各インデックスの元のフォルダの記録（source_folder.txt）を書き直す（updateIndexSourceFile）
    4. 検索対象のツリーでチェックを外していたフォルダの記録（searchExcludes）のうち、旧名・新名の下のものを消す（removeSearchExcludesUnder）。付け替えないため、外していたフォルダは検索対象に戻る。消せなくても改名は止めず、画面にエラーも出さない

    削除したときの処理（removeIndex）¶

    flowchart TD
    A["work\content_index\名前 を中身ごと削除<br>（別スレッド）"] --> B["取り込み一覧から行を除く<br>（removeStatusIndexName）"]
    B --> C["setting.config から外して保存<br>元のフォルダの記録を書き直す"]
    C --> D["そのインデックスの下の searchExcludes を消す<br>（removeSearchExcludesUnder。消えなくても止めない）"]
    1. work\content_index\<名前> を中身ごと削除する（\\?\ 付き）
    2. 取り込み一覧から、そのインデックスの クロール対象フォルダ の行と各ファイルの行を取り除く（removeStatusIndexName）
    3. setting.config から外して保存し、元のフォルダの記録を書き直す
    4. 検索対象のツリーでチェックを外していたフォルダの記録（searchExcludes）のうち、そのインデックスの下のものを消す（removeSearchExcludesUnder。手順 2 の直後に別スレッドの中で行う。消せなくても削除は止めず、画面にエラーも出さない）

    インデクサの removeDroppedFolders（クロール対象フォルダと取り込み対象）は、画面を通さずに設定を書き換えた場合の後始末として残す。画面から削除した場合は、その場で消えているため何もしない。

    エクスポート・インポート¶

    ［インポート…］［エクスポート…］は、一覧の右上の［アクション ▾］のメニューの項目に置く（［エクスポート…］は行の右クリックのメニューにも置く）。中身の zip の形式・exportIndex・importIndex の手順は インデックスのエクスポート・インポート を参照。

    部品 仕様
    ［エクスポート…］ チェックを付けた行に対して動く（2 件以上は書き出し先を 1 回だけ選び、1 つずつ書き出す）。押すとエクスポートのダイアログ（xaml/dialog_export.xaml。見出しの代わりに、書き出す対象の枠（名前。2 件以上は N 件のインデックス。その下にファイル数。大きさは数えていないので出さない。getIndexExportHeader）を上に置き、書き出し先のフォルダの欄 ExportPathBox・［参照…］・［エクスポート］・［キャンセル］。欄の初めはワークスペースのフォルダ。フォルダのドラッグ＆ドロップでも指定できる。欄の下に <名前>_インデックス_<yyyyMMdd>.zip として保存します、ボタンの上に橙の枠で このファイルには、元のファイルの本文と元のフォルダの場所が含まれます。元のファイルと同じように取り扱ってください。 を出す）を出す。［エクスポート］で、空なら 書き出し先のフォルダを指定してください。（testIndexExportInput）と出し、決まれば <名前>_インデックス_<yyyyMMdd>.zip（書き出し先のフォルダに同名があれば (2) …）で書き出す（getExportFileName）。書き出しは別スレッド（exportIndex）で行い、終わるまでステータスに エクスポートしています… と出す。終わったら インデックス [<名前>] を「<zip のパス>」に書き出しました（<件数> ファイル）（<名前> は exportIndex の戻り値の Name。tests/gui/index_archive.Tests.ps1 で名前まで確かめる）
    ［インポート…］ zip を選ぶダイアログ（Windows 標準のファイルを開くダイアログ）を出し、目録を読んで確かめる（readIndexArchiveInfo）。壊れている・別の版なら、その場でエラーを表示して終える。読めれば、インポートのダイアログ（xaml/dialog_import.xaml。表題は「インデックスのインポート」）を開く。上に zip の中身の枠（名前・エクスポートした日時 2026/09/27 10:00・2,530 ファイル・56.6 MB・v0.3.0。目録の exportedAt と大きさと版。getIndexImportHeader。注意の枠は置かない）を出し、その下に元のフォルダ（目録の値）と、欄の下の 1 行（見つかりました（緑）／元のフォルダがこの PC に見つかりません。検索はできますが、元のフォルダを設定するまで更新できません。（橙）／「<名前>」の元のフォルダと重なっています（赤）。有無は目録を読む別スレッドで調べ、入力を変えた後は［参照…］で選んだものだけ 見つかりました にする。getImportSourceCheckText）、名前（ラベルは 名前。既にあれば重ならない名前を提案）を出す。名前が今の一覧にあれば、橙で 同じ名前のインデックスがあります。［インポート］を押すと、上書きするか別の名前にするかを選べます。 を出す（getImportNameNoticeText）。名前を既にあるインデックスと同じにして［インポート］を押すと、上書き・別名・取りやめの確認ダイアログを出す。決まったら別スレッド（importIndex）でインポートし、終わったら一覧を読み直し、ステータスに件数と 高速検索は次の更新の後に効きます。、Warnings（同じ元のフォルダが別の名前で登録されているときなど）を出す（getImportResultStatus）。名前・元のフォルダのダイアログや上書きの確認を取りやめたときは、ステータスを インポートを取りやめました に書き換える

    排他: インデックス作成のロックで防げるのはインデクサだけで、一覧の名前の変更・削除・［設定］のワークスペースの切り替えは、このロックを取らずに content_index\・取り込み一覧・設定を書き換える。そこでエクスポート・インポートを別スレッドで行っている間と、次のものが動いている間は、互いに操作できないようにする。可否と押せなかったときの文言は、判断層の getIndexJobBlocker（動いているもの）・getIndexJobBlockedMessage（文言）・getIndexTabButtonsEnabled（表のボタン）だけで決め、画面の側（testIndexOperable・testWorkspaceChangeable・updateIndexingButton）は結果を使うだけにする（index_view.Tests.ps1 の表のテスト）。

    動いているもの 無効にするもの
    エクスポート・インポート ［＋ フォルダを追加］［編集…］［削除］［すべて更新］・行の［更新］・もう一方の［エクスポート…］［インポート…］・［設定］のワークスペースの［変更…］
    インデックス作成・削除 ［エクスポート…］［インポート…］

    ［設定］の［変更…］は、押した時点で testWorkspaceChangeable が getIndexJobBlocker でインデックス作成中・削除中・エクスポート・インポート中かどうかを確かめ、動いていれば getIndexJobBlockedMessage（エクスポート・インポートが終わるまでお待ちください。 など）を出して何もしない。別のセッション（別のプロセスの画面・将来の CUI）の名前の変更・削除との排他は扱わない。
