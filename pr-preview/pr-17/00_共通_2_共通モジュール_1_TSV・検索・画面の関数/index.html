    5.2.2 TSV の作成・検索¶

    関数 入力 出力 概要 詳細 使用元
    toSafeFileName name string ファイル名禁止文字を全角に置換 01_変換.md インデックス名（newIndexName）、以前の版のインデックスのシート名の照合（画面）
    encodeIndexPlace place string TSV のファイル名に入れる場所を符号化する（ファイル名禁止文字・制御文字・_・% を %XX に） 01_変換.md 6.2 節 toIndexFileName
    decodeIndexPlace place string encodeIndexPlace の %XX を元に戻す（それ以外の % はそのまま） 同上 splitIndexFileName（検索処理でも同じ）
    toIndexFileName place string インデックスの TSV のファイル名 <場所>.tsv（場所は encodeIndexPlace）。元のファイル名はフォルダ名にするため入れない。$maxFileNameLength（255）文字を超えれば例外 01_変換.md 6.1 節 変換（Excel・Word・PowerPoint）
    toLongPath path string ファイル操作に渡すパスの先頭に \\?\（ネットワークのパスは \\?\UNC\）を付け、260 文字を超えるパスも扱えるようにする。付いていればそのまま 01_変換.md 6.1 節 変換・検索
    fromLongPath path string toLongPath で付けた \\?\ を外す（Get-ChildItem の FullName から相対パスを求めるため） 同上 変換・検索
    replaceCellNewLine inputString string " で囲まれた範囲の改行（CRLF・CR・LF）を $cellNewLine に置き換える 01_変換_1_Excel.md formatTsv
    formatTsv content, firstRow（既定 1）, firstColumn（既定 1） string TSV 整形。N 行目・k 列目をシートの N 行目・k 列目にそろえる 01_変換_1_Excel.md prettyTsv
    prettyTsv 入力パス, 出力パス, firstRow（既定 1）, firstColumn（既定 1） bool 入力（UTF-16）を読み、formatTsv して UTF-8（BOM 付き）で保存。内容が空なら保存せず $false 01_変換_1_Excel.md 変換
    splitIndexTsvPath relPath @{Book; Place; RelDir} インデックスフォルダからの TSV の相対パスを、元のファイル名・場所・元のファイルのあるフォルダに分ける。今の形式（<ファイル名.xlsx>\<場所>.tsv）と以前の形式（フラット）の両方を扱う 02_検索.md 5.3 節 画面・検索処理（newTsvFiles）も同じ規則
    splitObjectPlace place @{Base; Kind} 図形・コメントの場所（<元の場所>[図形] 等）を、元の場所と種類に分ける。ふつうの場所は Kind が空 01_変換_7 6.1「図形・コメントの場所」 元のファイルを開く
    describePlace book, place @{Place; Kind} 画面の「場所」「種別」と検索結果ファイルに出す文字（[シート] 売上・テキスト、[ページ] 3（目安）・本文 など） 02_検索.md 5.1 画面・toResultLine
    splitIndexFileName fileName @{book; sheet} 以前の形式（フラット）のインデックスファイル名を元のファイル名・場所に分解し、場所を decodeIndexPlace で元に戻す（正規表現は $indexFileNamePattern） 同上 splitIndexTsvPath、変換（migrateFlatIndex）
    getIndexTsvCounts dir（既定 work\index） 相対パス → TSV 数の辞書 / $null インデックスの中のフォルダごとの TSV の数を数える（フォルダ・TSV をそれぞれ 1 回ずつ列挙する。TSV の無いフォルダは 0 件）。キーは変換一覧の相対パスと同じ。列挙できなければ $null 01_変換_5 変換（変換対象の決定）
    testIndexComplete row, relPath, counts bool 変換一覧の「済」の行に対して、インデックス（TSV）がそろっているかを返す。行の TSV 数より少なければ $false（変換し直す）。TSV 数が空・counts が $null のときは確認しない 同上 変換（変換対象の決定）
    publishIndexFiles fromDir, bookDir, stagingDir – 変換したTSVを stagingDir に集めてから、bookDir をフォルダごと入れ替える（作りかけのインデックスを残さない）。別ドライブでフォルダごと移せない場合は 1 件ずつ移す 01_変換.md 6.1 節 変換（publishTsv）
    removeDirectoryRetry path, tries（既定 3）, waitMilliseconds（既定 200） – フォルダを中身ごと削除する。ほかのアプリが一時的に掴んでいることがあるため、少し待って数回試す – 変換（インデックス・作業フォルダの削除）
    toResultLine book, location, lineNumber, line string ファイル名<TAB>場所<TAB>種別<TAB>行番号<TAB>該当行 を返す（場所・種別は describePlace の表示）。Excel はセル内改行を LF に戻し、Word・PowerPoint は " で始まるセルを " で囲む。場所のタブ・改行（Excel のシート名に付けられる）はスペースにする 02_検索.md 検索
    countTsvFields line int Excel に貼り付けたときのセル数（" で始まるセルは閉じる " までを 1 セルとする。先頭のセルが空でも数え落とさない） 02_検索.md 検索
    toColumnName number string 列番号を列名に変換（1 → A、27 → AA） 02_検索.md toResultHeader
    toResultHeader columnCount string 見出し行 ファイル名<TAB>場所<TAB>種別<TAB>行<TAB>A<TAB>B… を返す 02_検索.md 検索
    isValidRegex pattern bool 正規表現として正しいか – 検索・画面
    getIndexTsvFiles folders（既定 work\index。フォルダの文字列、または @{Root; RelPath; Recurse}（画面のツリーで選んだ範囲。Recurse が $false なら直下だけ）の配列）, onProgress（2000 件ごとに { param($count) } を呼ぶ） @{Folders; Files} 検索対象の TSV を列挙する。結果の相対パスは Root から求める。Folders はフォルダごとの @{Path; Root; Exists; Count}、Files は TSV のフルパス → @{Root; RelPath}（パス順・重複なし）。検索を始めるまでの待ち時間になるため、Get-ChildItem ではなく .NET の列挙を使い、相対パスも切り出しで求める（TSV 2 万件で約 6 秒 → 約 2 秒） 02_検索.md 検索・画面
    testIndexExists folders bool TSV が 1 件でもあるか（最初の 1 件で打ち切る） – 画面
    getIndexSummary folders @{Count; LastWrite; Missing} TSV の件数・最新の更新日時・存在しないフォルダ – 画面
    newSearchRegex word, simpleMatch, caseSensitive @{Regex; SimpleMatch} 検索条件から照合用の正規表現を作る（文字どおりならエスケープ、大文字と小文字を区別しないなら IgnoreCase、正規表現として不正なら文字どおりにする）。simpleMatch が偽でも、正規表現として不正なら文字どおりにする。1 行の照合は 5 秒で時間切れ 02_検索.md 4.2 検索・画面（一致箇所の強調）
    newFileFilter filter @{Include; Exclude} 対象ファイルの指定（*.xlsx;見積;!*old*）を、元のファイル名に対する正規表現にする（無い側は $null） 同上 searchIndex
    newPlaceExclude includeShapes, includeComments regex / $null 検索から外す図形・コメントの場所（名前の末尾 [図形] [コメント]）の正規表現。どちらも検索するなら $null 同上 searchIndex
    searchIndex word, tsvFiles, simpleMatch, limit, chunkSize, onProgress, shouldStop, caseSensitive, fileFilter, workerCount（並列のスレッド数。0 は自動）, cache（newTsvTextCache）, includeShapes, includeComments（図形・コメントの場所も検索するか。newPlaceExclude） @{Hits; SimpleMatch; Total; Truncated; Cancelled} TSV を検索する（照合は searchTsvFiles＝.NET の StreamReader＋[regex]）。Hits は PSCustomObject（Root・RelPath・RelDir・FileName・Book・Location・LineNumber・Line）。Total は対象ファイル・図形とコメントの指定で絞った後の TSV の数。chunkSize 件ずつ検索して進捗を知らせ、上限・中止に対応する。TSV が多ければ複数スレッドで並行して検索する（結果の順は変わらない）。読めない TSV は飛ばす 02_検索.md 検索・画面
    newTsvTextCache maxChars（既定 6,400 万文字） @{Texts; Chars; MaxChars} 検索で読んだ TSV の内容を次の検索で使い回す入れ物。更新日時・サイズが変わった TSV は読み直す 02_検索.md 画面
    toSearchResultLines hits @{Header; Lines} 検索結果ファイルの見出し行と各行（相対フォルダ付き toResultLine、最大セル数の toResultHeader） 02_検索.md 検索・画面
    writeSearchResult writer, word, hits – 1 ワード分の 【検索文字列　X】 N 件・見出し行・各行・空行を書き出す 02_検索.md 検索・画面
    splitTsvCells line string[] TSV の 1 行をセルに分ける（" で囲まれたセルは 1 セルとし、囲みを外す） – –
    readTsvContext path, lineNumber, before（既定 3）, after（既定 3） @{LineNumber; Line} の配列 TSV の lineNumber 行目と前後の行を返す（行の数え方は searchIndex と同じ）。読み込みは PowerShell（StreamReader）で先頭から目的の行まで読む。読めなければ空 03_画面_2_検索タブ.md 4.7 画面

    5.2.3 元のファイルの特定・画面¶

    関数 入力 出力 概要 詳細 使用元
    writeSourceFolderFile folders（@{Path; Name} の配列）, dir（既定 $indexDir） – 各インデックスのフォルダ（dir\<インデックス名>）に 元のフォルダ.txt（インデックス名<TAB>変換対象フォルダ）を書き出す。以前の版が dir 直下に書いた全インデックス分のファイルは、各フォルダへ移してから消す 01_変換.md 変換
    readSourceFolderFile dir Dictionary（インデックス名 → フォルダパス） dir 直下の 元のフォルダ.txt を読む。無ければ空（dir の下は探さない。インデックスのフォルダの下は元のファイル 1 つにつき 1 フォルダになるため） 同上 getSourceFolderMap
    getSourceFolderMap dir, statusPath（既定 $statusFile）, settingsPath（既定 $settingsFile） Dictionary（インデックス名 → 元のフォルダ） インデックス名に対する元のフォルダ。dir 直下の 元のフォルダ.txt → （既定のインデックスなら）変換一覧 → 設定（targetFolders / indexSources） の順に上書きするため、設定の「今の置き場所」が最も優先される 03_画面_2_検索タブ.md getSourceLocation
    getSourceLocation hit, maps（フォルダ → 対応 のキャッシュ） @{Name; Folder; Rest; Known} 検索結果のインデックス名・元のフォルダ・その下の相対フォルダ。検索対象フォルダの対応 → その下の <インデックス名> のフォルダのもの → 検索対象フォルダ自身・その親のもの（インデックス名のフォルダを直接指定した場合）の順に使う。分からなければ Known = $false・Folder = 空（Name は返すため、フォルダを選んでもらえば設定に記録できる） 同上 resolveSourcePath, 画面
    joinSourcePath folder, rest, name string フォルダ・相対フォルダ・ファイル名をつなぐ（ドライブ直下でも \ を重ねない） – 画面
    findMovedSource picked, rest, book @{Path; Root} / $null 選んだフォルダの中から元のファイルを探す。選んだフォルダを元のフォルダ、その下のフォルダ…の順に当てはめて試し、見つかったファイルと、元のフォルダに当たるフォルダ（Root）を返す 03_画面_2_検索タブ_1 4.5.2 画面
    resolveSourcePath hit, maps string / $null 検索結果の元のファイルのパス（ファイルがあるかは確かめない）。元のフォルダが分からなければ $null 03_画面_2_検索タブ.md 画面
    readSearchOption / writeSearchOption path（既定 $settingsFile） / option（@{UseRegex; CaseSensitive; FileFilter; IncludeShapes; IncludeComments} のうち変える項目）, path @{UseRegex; CaseSensitive; FileFilter; IncludeShapes; IncludeComments} / – 画面の検索条件（setting.config の useRegex / caseSensitive / fileFilter / includeShapes / includeComments。無ければオフ・空、図形とコメントはオン）。保存は option にある項目だけを変える – 画面
    getConversionState since, path @{Exists; Folders; Total; Pending; Failed; Done; ConvertedSince; Updated; FailedRows; IndexStats} 変換一覧の状態ごとの件数、失敗したファイルの行（FailedRows。変換日時の新しい順）、インデックス名ごとの集計（IndexStats。getIndexStats。変換一覧を読み直さずに済むよう同じ読み込みから作る） 03_画面_4_状態と操作の流れ.md 画面
    getOfficeProcesses – プロセス情報の配列 実行中の Excel・Word・PowerPoint（Id・ProcessName・AppName・Background・StartTime・MemoryMB・Title）。MainWindowHandle が 0 ならバックグラウンド 03_画面_3_プロセス停止タブ.md 画面
    stopOfficeProcesses ids @{Id; Stopped; Message} の配列 Stop-Process -Force で終了し、成否と理由を返す 03_画面_3_プロセス停止タブ.md 画面
