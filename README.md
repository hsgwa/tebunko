# tebunko

[![test](https://github.com/hsgwa/tebunko/actions/workflows/test.yml/badge.svg?branch=main)](https://github.com/hsgwa/tebunko/actions/workflows/test.yml)
[![codecov](https://codecov.io/gh/hsgwa/tebunko/branch/main/graph/badge.svg)](https://codecov.io/gh/hsgwa/tebunko)

**tebunko**（手文庫）は、手元に置いて日常的に引く文書の箱です。Windows で Office ファイルを扱う道具箱で、いま入っているツールは検索の `tebunko_grep`、将来 `tebunko_diff`（比較）を加える予定です。

Office ファイルを「場所」ごとに TSV へ変換してインデックス化し、文字列を一括検索するツールです。
操作はすべて画面（`tebunko_grep.bat`）から行います。

| 種類 | 拡張子 | 場所（検索結果の「場所」列） |
|---|---|---|
| Excel | .xlsx / .xlsm / .xls / .xlsb | シート |
| Word | .docx / .docm / .doc | ページ（目安）・ヘッダー/フッター・脚注 |
| PowerPoint | .pptx / .pptm / .ppt | スライド・ノート・フッター |

Windows PowerShell 5.1 と Microsoft Excel が必要です（追加のインストールは不要です）。
Word・PowerPoint は、旧形式（.doc / .ppt）やパスワード付きのファイルを変換するときだけ使います（.docx / .pptx は Word・PowerPoint が無くても変換できます）。

## フォルダ構成

```
tebunko_grep/
├─ tebunko_grep.bat             # 画面を開く（インデックス作成・検索・プロセス停止）
├─ setting.config         # 画面が保存する設定（自動作成。git 管理外）
├─ scripts/               # PowerShell 本体
│   ├─ tebunko_grep/gui.ps1     # 画面（tebunko_grep/xaml/tebunko_grep.xaml が画面の定義）
│   ├─ tebunko_grep/convert.ps1  # 変換処理（画面がウィンドウ無しで起動する）
│   ├─ shared/office/office_reader.ps1  # Word・PowerPoint の読み取り
│   ├─ tebunko_grep/lib.ps1         # パス定義・共通関数
│   └─ tebunko_grep.ico       # 画面のアイコン（タイトルバー・タスクバー）
├─ tests/                 # Pester テスト（.\tests\run.ps1）
├─ tools/                 # 配布物・カタログ・ハッシュ一覧を作る、コミット前の検査（開発用）
├─ sbom.cdx.json          # 部品表（CycloneDX。第三者の部品は 0 件）
├─ SECURITY.md            # 安全性の説明と脆弱性の連絡先
├─ LICENSE                # ライセンス（MIT）
└─ work/                  # 自動生成（git 管理外）。消せば最初からやり直し
    ├─ index/             # 変換済み TSV（インデックスのフォルダごと別の PC へコピーして検索できる）
    ├─ 変換一覧.tsv       # 各ファイルの更新日時・状態（Excel で開ける）
    ├─ 変換ログ.txt       # 直近の変換の記録
    └─ 検索結果.txt       # ［結果をファイルに出力］で書き出す検索結果
```

## 配布とインストール

インストーラーはありません。**`tebunko_grep` フォルダを zip などで配り、展開して `tebunko_grep.bat` をダブルクリック**すれば動きます。
コピー先は PC の中でも共有フォルダでもかまいません（配布前に `work/` と `setting.config` は消してかまいません。どちらも使う PC ごとに自動で作られます）。

実行ポリシーの変更は不要です（`RemoteSigned` のまま動きます。管理者権限も不要）。

- **初回だけ、ダウンロードした zip 由来のセキュリティ警告が 1 回出ます。** `tebunko_grep.bat` をダブルクリックすると Windows の「開いているファイル - セキュリティの警告」（発行元を確認できません）が出るので、［実行］を押してください。以降は出ません。
  - これは、ダウンロードした zip を展開したファイルに「外部由来」の印が付くためです。`tebunko_grep.bat` が起動時にこの印を消すので、2 回目からは警告なしで起動します。
  - `tebunko_grep.bat` を右クリック →［プロパティ］→ 下部の［ブロックの解除］にチェック → ［OK］としてから起動すれば、初回の警告も出ません（任意）。

起動中はタスクバー・タイトルバーに tebunko_grep のアイコンが出ます。よく使う場合は、`tebunko_grep.bat` を右クリック →［スタート メニューにピン留めする］や、起動中のタスクバーのボタンを右クリック →［タスク バーにピン留めする］で置けます（ツールは自動ではショートカットを作りません）。

## 使い方

`tebunko_grep.bat` をダブルクリックすると画面が開きます。
すでに開いているときにもう一度起動すると、**二重には開かず、開いている画面が前面に出ます**（最小化していれば元に戻ります）。

### 1 インデックス管理

インデックスを **作成・編集・削除** し、中身（検索用の TSV）を作るタブです。

1. ［新規作成…］を押し、Office ファイルのあるフォルダとインデックス名を指定します（パスの貼り付け・［参照…］・ドラッグ＆ドロップ。一覧へのドラッグ＆ドロップでも作れます）。
   ［参照…］は**エクスプローラーのような画面**で選べます。左のツリー（よく使う場所・ドライブ）と右の一覧（フォルダと、そこにある Office ファイル）を見ながらたどれ、上のアドレスバーにパスを貼り付けて移動できます。選べるのはフォルダだけで、ファイルは目印として薄く表示されます（Office ファイルは緑）。戻る・進む・1 つ上への移動は、ボタンのほか、マウスのサイドボタンや `Alt+←` `Alt+→` `Alt+↑` `BackSpace` でも操作できます（エクスプローラーと同じ）。
2. インデックス一覧で、変換するインデックスにチェックを付けます。
3. ［変換を開始］を押します。まず**変換対象を数え、インデックスごとに「何件変換するか」を確認する画面**が出ます。
   更新されたファイルが無いインデックスは「更新不要」と表示されます。内容を見て［変換を開始］を押すと変換が始まり、［キャンセル］なら何も変換しません。
4. 変換は裏で実行され、画面に進み具合（件数・残り時間）が表示されます。途中で止めるときは［中止］を押します（変換中のファイルが終わったところで止まり、次回は続きから変換します）。

一覧には、インデックス名・元のフォルダ・フォルダの有無・ファイル数・最終変換日時が並びます。

- ［編集…］でインデックス名と元のフォルダの場所を変えられます（行のダブルクリックでも開きます）。
  **名前を変えても、変換済みのインデックスは作り直しません**（`work/index` のフォルダごと名前を変え、`work/変換一覧.tsv` の記録も付け替えます）。
- ［削除］でインデックスを削除します。`work/index/<名前>/` の TSV と `work/変換一覧.tsv` の記録もその場で削除します（元のフォルダと Office ファイルは削除しません）。
  一時的に変換しないだけなら、削除せずに「変換」のチェックを外してください（インデックスは残り、検索対象にも残ります）。
- 変換中は、作成・編集・削除はできません（変換が終わるまでお待ちください）。
- チェックを付けたインデックスごとに `work/index/<インデックス名>/` に TSV ができます。
- 各ファイルの更新日時・サイズ・状態（未変換・済・失敗）を `work/変換一覧.tsv` に記録します。
  2 回目以降は、この一覧と比べて**更新されたファイル・新しいファイルだけ**を変換します。
  元ファイルを削除・名前変更した場合は、古い TSV を削除します。
- **Excel・Word・PowerPoint のフォルダを丸ごと移した場合**（別のドライブ・共有フォルダへ移動した、ドライブ名が変わった等）は、
  インデックス一覧でそのインデックスを選び、［編集…］で新しい場所を指定してください。
  インデックスはそのまま使うので、**全件の変換をやり直しません**（次の変換では、更新されたファイルだけを変換します）。
  フォルダ名を変えて移した場合も同じです。削除して作り直すと別のインデックスになり、全件変換になります。
- PC が止まった等で途中で終わった場合も、次回は続きから再開します
  （そのとき変換していたファイルは最後に回し、続けて 2 回止まったファイルは「失敗」にします）。
- 1 ファイルの変換に 10 分以上かかった場合（Excel が応答しなくなった等）は、Excel を強制終了して
  そのファイルを「失敗」とし、次のファイルへ進みます。
- 260 文字を超える長いパスのファイルや、名前の長いファイルも変換・検索できます（Windows の設定変更は不要）。
- **ファイルサーバーのフォルダも指定できます。** ネットワークドライブ（`Z:\見積`）でも UNC パス（`\\server\share\見積`）でもかまいません。
  同じフォルダを別の書き方で登録しても、同じフォルダとして扱うので、インデックスが二重にできることはありません。
  `%USERPROFILE%\Documents\見積` のような環境変数、`/` 区切り、`.` `..` を含むパスも、そのまま貼り付けられます。
  サーバーに一時的につながらないときは、そのフォルダだけ変換せずに続け、できているインデックスは消しません。
- 変換に失敗したファイル（パスワード付きなど）は一覧の状態が「失敗」になり、原因が「エラー」列に記録されます。
  失敗したファイルと原因は、［1 インデックス管理］タブの「変換に失敗したファイル」の一覧にも表示されます。
  更新されない限り次回以降はスキップし、［変換を開始］の確認の画面で「失敗したファイルも再変換する」を選べます。
- 変換を続けられないエラー（変換対象フォルダが無い等）は画面に表示されます。変換の詳しい記録は `work/変換ログ.txt` にあります。

### 2 検索

ワードを入れて Enter を押すと、結果が画面の表に出て、一致箇所が黄色で表示されます。
ダブルクリックで元のファイルを開きます（Excel は該当シート・セルを選択した状態で開く）。
［開き方］で「読み取り専用」（誤って上書きしない）や「新規」（元のファイルを基にした無題のブック・文書。元のファイルを占有しないため、ほかの人が編集中の共有ファイルも開けます）を選べます。選んだ開き方は次回も引き継ぎ、右クリックメニューからはその時だけ別の開き方でも開けます。
［正規表現を使う］をオンにしない限り、`(株)` や `1.5` も文字どおりに検索します。
サクラエディタの Grep と同じように、［大文字と小文字を区別］と
「対象ファイル」（元のファイル名のワイルドカード。例: `*.xlsx;見積;!*old*` は、.xlsx か名前に「見積」を含むファイルのうち「old」を含まないもの）で条件を指定できます。条件は次回も引き継ぎます。

- ［結果をファイルに出力］で `work/検索結果.txt`（ファイル名・場所・行番号・該当行のタブ区切り）に書き出せます。
  結果をすべて選択して Excel に貼り付けると、4 列目以降に該当行のセルが元の列の順に並びます。
  見出しの列名（A, B, C…）と行番号で、元のセル位置が分かります。セル内改行のあるセルも 1 セルのまま貼り付けられます。
- セル内改行は、正規表現の `.` にマッチします（例: `1行目.2行目`）。
- Excel のセルは**シートで表示されている形**で検索します。セルの文字は長くても（Excel の上限 32,767 文字まで）そのまま検索できますが、
  **数値のセルは表示形式によって見つからないことがあります**。表示形式が「標準」の 12 桁以上の数値はシートでも指数表記（`4901234567894` → `4.90123E+12`）になるため、その番号では検索できません。
  「#,##0」のセルも桁区切り付き（`1,234,568`）で検索します。JAN コード・伝票番号などは、表示形式を「文字列」にするか、先頭に `'` を付けて入力すると検索できます。
- 検索対象のインデックスは［変更…］で追加できます（既定は `work/index/`）。

#### インデックスを別の PC で使う

1. 変換した PC の `work/index/<インデックス名>/` フォルダ（`見積` など、変換したフォルダごとのフォルダ）を、
   別の PC の `work/index/` の直下にコピーします（USB メモリ・共有フォルダなど）。`work/index/` ごとコピーしても構いません。
   各フォルダには元のフォルダの場所を記録した `元のフォルダ.txt` が入っているので、フォルダごとコピーしてください
   （古い版で作ったインデックスには無いため、コピー元の PC で一度［変換を開始］を押すと作られます）。
2. 別の PC で `tebunko_grep.bat` を開くと、コピーしたインデックスが［2 検索］の検索対象に並び、そのまま検索できます。
3. 検索結果をダブルクリックすると元のファイルを開きます。元のファイルが見つからない場合（ドライブ名・共有フォルダのパスが違う等）は、
   フォルダを選ぶかを聞かれます。元のファイルのあるフォルダ（変換したフォルダに当たるフォルダ、またはファイルのあるフォルダ）を選ぶと、
   その中からファイルを探して開きます。選んだ場所は**そのインデックスの元のフォルダとして記録**され、
   同じインデックスのほかのファイルは次から聞かれずに開けます。
   なお、ネットワークドライブと UNC パスの違いだけ（インデックスは `Z:\見積`、この PC では `\\server\share\見積`）の場合は、
   この PC に同じ共有フォルダのドライブが割り当てられていれば、聞かれずにそのまま開けます。

### 9 プロセス停止

変換を異常終了させた場合などに残った Excel・Word・PowerPoint を、一覧から選んで終了できます。

### その他

- すべて変換し直したい場合は、`work/` フォルダを削除してから［変換を開始］を押してください。
  1 つのインデックスだけ作り直したい場合は、そのインデックスを［削除］してから、同じフォルダで作成し直してください。
- 検索できない文字（図形・SmartArt・コメントなど）や扱えないファイルは「[制約](#制約)」を参照してください。

## 制約

インデックスに入るのは、**変換した時点で「セル」「段落」「表」として保存されている文字**だけです。
そのため、次のものは検索できません。

### 検索できない文字

| 種類 | 内容 |
|---|---|
| Excel の図形・テキストボックス | シート上に置いた図形・テキストボックス・ワードアートの文字は入りません（Excel はセルだけを取り出すため）。Word・PowerPoint のテキストボックスは検索できます |
| SmartArt・グラフ内の文字 | グラフのタイトル・凡例・データラベル・SmartArt の文字は、Excel・Word・PowerPoint いずれも対象外です |
| 埋め込みオブジェクト | 文書に貼り付けた Excel の表・OLE オブジェクト・PDF などの中の文字 |
| コメント（メモ） | Excel のコメント・メモ、Word のコメント、PowerPoint のコメント |
| 画像の中の文字 | 写真・スキャンした文書の文字（文字認識（OCR）は行いません） |
| Excel の非表示シート・グラフシート | 非表示・完全に非表示のシートと、グラフだけのシートは変換しません。PowerPoint の非表示スライドは `スライドNNN（非表示）` として検索できます |
| Excel のヘッダー・フッター | 印刷時のヘッダー・フッターは対象外です（Word・PowerPoint のヘッダー・フッターは検索できます） |
| PowerPoint のスライドマスター・レイアウト | マスター・レイアウトに直接書いた文字。各スライドのフッターは `ヘッダー・フッター` として検索できます |
| Word の削除済みの文字・フィールドコード | 変更履歴で削除された文字・移動元と、`{ }` のフィールドコードそのもの（画面に表示されている結果の文字は検索できます） |
| ファイル名・フォルダ名 | 検索するのはファイルの中身だけです（ファイル名は［対象ファイル］での絞り込みに使えます） |

### 変換できないファイル

- **Excel・Word・PowerPoint 以外は対象外です。** 変換するのは
  `.xlsx` `.xlsm` `.xls` `.xlsb` `.docx` `.docm` `.doc` `.pptx` `.pptm` `.ppt` だけで、
  PDF・テキスト・CSV・メール・その他のアプリのファイルは変換しません。
  テンプレート（`.xltx` `.dotx` `.potx` など）と、`~$` で始まる Office のロックファイルも対象外です。
- **パスワード付きのファイルは変換できません**（一覧の状態が「失敗」になります）。
- 旧形式（`.doc` / `.ppt`）の変換には Word / PowerPoint が必要です。入っていない PC では「失敗」になります（`.xls` は Excel で変換します）。
- 1 ファイルの変換に 10 分以上かかると「失敗」になります。
- 書き出しが約 1GB を超える巨大なシート（100 万行規模）は、メモリ不足で「失敗」になります。

### 検索の制約

- **1 回に検索できるのは 1 ワードです。** 複数ワードの AND・OR 検索はできません
  （1 行の中の並びなら、［正規表現を使う］で `見積.*確定` のように書けます）。
- **一致は 1 行単位です。** 1 行とは、Excel ではシートの 1 行、Word・PowerPoint では 1 段落または表の 1 行です。
  **複数行にまたがる文字列は見つかりません**（1 行に複数ヒットしても 1 件と数えます）。
- **隣のセルにまたがる文字列も、文字どおりの検索では見つかりません。** セルの区切りはタブなので、
  ［正規表現を使う］で `商品名\t単価` のように書けば見つかります。
- セル内改行は正規表現の `.` にマッチします（`1行目.2行目`）が、改行をはさんだ文字をそのまま連結したワード（`1行目2行目`）は見つかりません。
- **数値のセルは、表示形式によって見つからないことがあります**（［2 検索］の説明を参照）。
- 検索結果は 10,000 件で打ち切ります。
- 正規表現の照合が 1 行あたり 5 秒を超えた場合は、検索を中止します（終わらない正規表現を避けるため）。

### インデックス・動作環境

- **インデックスは変換した時点の内容です。** 元のファイルを編集しても、［変換を開始］を押すまで検索結果には反映されません。
  更新の有無は更新日時（秒まで）とサイズで判定するため、1 秒以内に同じサイズのまま書き換えた場合などは変換されません
  （その場合は、そのインデックスを［削除］して作成し直すか、`work/` を削除して作り直してください）。
- **Word のページ番号は目安です**（ファイルにページの情報が無いため、Word が保存時に記録したページ区切りと改ページから数えます）。
  プログラムで作成した文書など、ページ区切りが記録されていない文書は全体が `ページ001` になります。
- 変換中は Excel・Word・PowerPoint を自動で操作します。変換対象フォルダのファイル自体は作業用にコピーしてから開くため占有しませんが、
  変換中は手作業での Office の使用を控えてください（利用者が使用中のアプリを使う場合があります）。
- Windows 専用です。Windows PowerShell 5.1 と Microsoft Excel が必要です。

## 安全性（導入審査向け）

本ツールは PowerShell スクリプトだけで動きます。第三者のライブラリを使わず、ネットワーク通信・動的なコード実行・レジストリの変更・管理者権限を必要としません。変換対象のファイルは作業フォルダへコピーしたものを読み取り専用・マクロ無効で開くため、原本を書き換えません。

根拠と確認手順は [docs/04_安全性.md](docs/04_安全性.md) にまとめています。第三者のツールによる検査では、PSScriptAnalyzer（Microsoft の静的解析）の安全性にかかわるルールが指摘 0 件、Microsoft Defender のスキャンが検出 0 件です。

部品表は [sbom.cdx.json](sbom.cdx.json)（第三者の部品は 0 件）、脆弱性の連絡先は [SECURITY.md](SECURITY.md) にあります。

主張は次のコマンドで機械的に検査できます（PSScriptAnalyzer を導入していれば静的解析も含めて検査します）。

```powershell
.\tests\run.ps1 -Tag Meta
```

**ただし、インデックス（`work/index/`）は元の文書の本文を平文で保持し、元のファイルのアクセス権を引き継ぎません。** ツールを置いたフォルダのアクセス権は、変換対象フォルダと同等以上に制限してください（[docs/04_安全性.md](docs/04_安全性.md) の 4.3）。

配布物が改ざんされていないことを確認できるよう、配布前に `.\tools\new_release_files.ps1` でカタログ（`tebunko.cat`）とハッシュ一覧（`SHA256SUMS.txt`）を作り、zip に同梱できます。受け取った側は `Test-FileCatalog` で検証できます（証明書は不要）。
GitHub の Releases で配る zip には、この 2 つを同梱しています（`v` で始まるタグを push すると、テストを通したうえで `.github/workflows/release.yml` が作ります）。
