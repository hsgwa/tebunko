## 各ファイルの章立て（すべて同じ順）

1. **役割** … 何のための領域か（2〜3 行）。Figma の部品（340 のノード ID）と、使う画面（106・148 の画面の記号とノード ID、`../png/` の画像名）。
2. **置き場所** … XAML のパス、親のどこに差すか（`ContentHost` など）、読み込みの仕方。
3. **部品の木** … そのまま書き写せる XAML の骨組み（```xml）。
   - Grid の `RowDefinitions`・`ColumnDefinitions`、Width・Height・MinWidth・MaxWidth、Margin・Padding、揃え、Style のキー、`x:Name` をすべて書く。
   - 中身の文言は `{文言の ID}` で書く。
4. **寸法と色** … 要素ごとの表。要素（x:Name か層の名前）・大きさ・余白・地の色・枠・文字の Style・文字の色（すべて theme のキー名。値を括弧で添える）・角丸・アイコン（Lucide の名前・大きさ・線の太さ）。
5. **状態ごとの見え方** … 状態（画面の記号）を行、要素を列にした表。出す・出さない・有効・無効・文言の ID・選んだ見た目を書く。状態に入る条件（判断層の入力のどの値か）も書く。
6. **文言** … 表。文言の ID・全文（可変の所は `{件数}` のように）・使う状態。半角・全角、数と単位の間の空白まで Figma のとおりに書く。キー操作のヒントは書かない（UI に出さない決まり）。
7. **操作と振る舞い** … 表。きっかけ（クリック・ホバー・選ぶ・ダブルクリック・ドラッグ・文字を打つ）・何が起きるか・呼ぶ関数・次の状態。ホバー・押した・無効・フォーカスの見た目、Tab の順、ツールチップの文言。
8. **リサイズ** … 最小・最大、どこが伸びるか、切る（`TextTrimming`）・折り返す（`TextWrapping`・WrapPanel）、スクロール（`ScrollViewer` の向きと `Auto`）。1024×640 と 1600×1000 のときの見え方。
9. **判断層** … 関数ごとに、名前（PowerShell の動詞-名詞でなく、今のコードの名前の付け方に合わせる）・入力・出力（ハッシュテーブルのキーと型）。テストにそのまま使える `-TestCases` の表（入力 → 期待値）。
10. **画面層** … x:Name ごとのイベントの配線、判断層の出力を画面に写す手順。UI スレッドの扱い（重い処理は別のスレッド、戻りは Dispatcher）。
11. **受け入れ** … 見比べる Figma の画像（`../png/` の名前と窓の大きさ）、確かめる点の箇条（ピクセルで分かるもの）。

## 書き方の決まり

- 日本語で書く。数値はピクセル（WPF の DIP）。窓 1280×820 のときの値を基本とし、変わるものだけ大きさごとに書く。
- 色は theme のキー名で書き、値（`#RRGGBB`）を括弧で添える。キーが無い色は `../figma_wpf_map.md` の「食い違い」に足す案として書く。
- アイコンは Lucide（lucide-static 1.50.0）の名前で書く。線の太さは表示の大きさ × 2/24。
- 人名・社名は架空のもの（`(株)山田商事`・`山田`・`佐藤`）、メールは `example.com`。
- 推測で埋めない。Figma で決まっていないものは「未定」と書き、各ファイルの末尾の「決めること」に集める。
