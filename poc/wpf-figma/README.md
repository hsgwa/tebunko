# poc: Figma の UI を WPF で再現する（段 1）

Figma の ToBe（決定の記録の面 106:50・プロトタイプ 148:50）の見た目を、今の作り方（PowerShell 5.1 + WPF、追加のインストール無し）でどこまで再現できるかを確かめる PoC。段 1 は「共通（トークン・フォント・部品・見る道具・比べる道具）＋起動画面＋検索画面」を対象にする。

このフォルダは本体（`scripts/`・`tests/`・`docs/`・`tools/`）から独立しており、`scripts/` のファイルを読み込まない。本体に戻すかどうかは、この PoC を見てから別に決める。マージしない前提で、作業ツリーの中だけに置く。

## 動かし方

```
powershell -ExecutionPolicy Bypass -File poc\wpf-figma\show.ps1
powershell -ExecutionPolicy Bypass -File poc\wpf-figma\compare.ps1
```

`show.ps1` はフレームを選んで原寸表示する道具、`compare.ps1` は 26 枚すべてを `reference/*.png` と比べ、`out/<フレーム名>.diff.png` と差分率の表を出す道具。

## 状態（2026-10-02）

- `theme.xaml`・`xaml/*.xaml`（21 状態＋部品）・`dummy.ps1`・`show.ps1`・`compare.ps1` を作り込み、26 枚すべてをレンダリングして `reference/*.png` と比べた。
- `compare.ps1` の `diff.png` を 26 枚すべて見て、色・レイアウト・文言の食い違いを洗い出し、直せるものは直した（吹き出しの背景色、プレビュー表の欠けていた行、高速検索の表示の外枠カード、H フレームの開いたドロップダウン、`探す範囲` の部品が中央寄せになっていた崩れ、`フルパスのツールチップ` の行が中央寄せになっていた崩れ、H 系フレームが共有する検索結果一覧の文言の欠け・誤字（「本文（常に対象）」の欠け、議事録メモの文末の「る」の欠けなど）など）。
- 直したあとに残る差分は、`compare.ps1` の `diff.png` を見ながら 1 枚ずつ原因を確かめ、文字・アイコンの描画エンジンの違いによるアンチエイリアシングなど、この作り方では埋まらないものだけであることを確認した。個別の内容は下の「再現できなかったところ」に書く。

## トークンの対応（Figma の値・キー名・今の theme.xaml の値）

Figma は Variables・Styles を使っておらず、値を直接指定している（段 1 の計画どおり）。そのため `theme.xaml` も、近い値をまとめずに Figma の値をそのままキー名に埋め込んだ（例 `Ink.202124` は `#202124`）。キー名を見れば Figma の元の値が分かる形にしてあり、個別の対応表は作らず、種類ごとにまとめる。

| 種類 | 件数 | キーの形 | 備考 |
|---|---|---|---|
| 色（`SolidColorBrush`） | 29 | `Ink.*`・`Accent.*`・`Bg.*`・`Select.*`・`Line.*`・`Border.*`・`Ok.*`・`Warn.*`・`Danger.*`・`Chip.*`・`Hit.*`・`Folder.*`・`Excel.*`・`Disabled.*`・`White`（例 `Ink.202124`＝`#202124`） | 完全一致。16 進の RGB をそのまま使っているため、色のずれは起きない |
| 余白・間隔（`Thickness`・`sys:Double`） | 6 | `Pad.*`・`Gap.*`（例 `Pad.Button`＝`16,7,16,7`） | 完全一致。ピクセル値をそのまま使う |
| 角丸（`CornerRadius`） | 2 | `Radius.3`・`Radius.4` | 完全一致 |
| 影（`DropShadowEffect`） | 3 | `Shadow.Card`・`Shadow.Dialog`・`Shadow.Small` | Figma のぼかしの値を `BlurRadius` にそのまま当てているが、ぼかしの計算の仕方が Figma（レイヤーぼかし）と WPF（`DropShadowEffect`）で違うため、広がり方は一致しない（下の「再現できなかったところ」） |
| アイコン（`Geometry`） | 17 | `Icon.*`（例 `Icon.Folder`・`Icon.Search`） | Figma のベクターを手で近似した簡易パス。SVG そのものは書き出していないため、厳密な形の一致は確かめていない（下の「再現できなかったところ」） |
| 文字サイズ・太さ（`Style TargetType="TextBlock"`） | 15 | `Text.10`〜`Text.28`（`.Muted`・`.Bold`・`.Medium` の派生を含む） | `FontSize` は Figma の値のまま。書体は下の「フォント」のとおり Rethink Sans＋Yu Gothic UI の組み合わせのため、字形・字間は完全一致しない |
| 部品のスタイル（`Style TargetType="Button"` ほか） | 20 | `Btn.*`・`CheckBox.Tree`・`Chip`・`NavBadge`・`StatusBadge`・`Bubble`・`Banner`・`TextBox`・`EmptyIconRing`・`TreeChevron`・`ScrollBar` 系 | 色・余白・角丸は上の色／余白／角丸のトークンを組み合わせて使う。`ControlTemplate` は Figma のレイヤー構成を見ながら手で組んだもの |

内訳は `theme.xaml` 本体（419 行）を参照。

## 再現できなかったところ

残差分率が 1% を超える 25 枚すべての `diff.png` を見て原因を分け、直せるものは「状態」に書いたとおり直した。直したあとも残る差分は、次のどれかで説明できる（色やレイアウトそのものがずれている箇所は無い）。

- **テキスト・アイコンのアンチエイリアシング**: Figma のラスタライザと WPF の文字描画エンジン（ClearType/DirectWrite）は、同じフォント・同じ大きさでも 1 ピクセル単位ではにじみ方が異なる。`正規表現の吹き出し`（部品、差分率 20.46%）・`高速検索の表示`（部品、差分率 46.2%）は、背景色・文言を参照画像に合わせたあとも `diff.png` で文字の輪郭だけが赤くなっており、色・レイアウトのずれではないことを確認した。`高速検索の表示` は 1 枚の中に短い文を 6 行分すき間なく詰め込む構図のため、文字が占める面積の割合が 26 枚の中で最も高く、差分率も最も高い。文字・アイコンが多いフレームほど差分率が高く出るのは、ほぼこれが理由。
- **影のぼかしの広がり方**: Figma のぼかしの値をそのまま `DropShadowEffect` の `BlurRadius` に当てているが、計算の仕方が Figma と違うため、広がり方は厳密には一致しない（`theme.xaml` にも記載）。
- **アイコンの形**: Figma のベクターを手で近似した簡易パスを使っている。SVG そのものを書き出していないため、厳密な一致は確かめていない。
- **`フルパスのツールチップ`（部品、差分率 36.52%）**: 行の位置を左寄せに直したあとは、`diff.png` でタイトルの説明文・ファイル名・吹き出しの文字の輪郭だけが赤くなっており、位置・色のずれは無い。571×100 という小さい部品の中で文字が占める面積の割合が高いため、上のアンチエイリアシングの影響がそのまま差分率に出ている。
- **H 系フレームの個別の内容確認**: `H` と `H-R` は検索結果一覧の文言を参照画像と 1 行ずつ突き合わせ、見つかった誤字・欠け（「本文」の「（常に対象）」の欠け、議事録メモの行の文末の「る」の欠けなど）を直した。`H-T1`・`H-B` は「開く」のドロップダウンが開いていないことを個別に確認した。一方 `H-W`・`H-P`・`E13`・`H-範囲`・`H-範囲2`・`H-row3`・`H-row4`・`H-saved` は計画の設計の記述から dummy の状態を作ったもので、件数・ファイル名など内容の細部まで 1 行ずつ参照画像と突き合わせてはいない（レイアウトの崩れが無いことは `xaml/search.xaml` の `Width` 指定を総点検して確認済み）。

`compare.ps1` は、上の直しをすべて反映した最終の状態で 26 枚を再実行し、その結果を「比べた結果」の表に載せた。
