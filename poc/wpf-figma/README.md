# poc: Figma の UI を WPF で再現する（段 1）

Figma の ToBe（決定の記録の面 106:50・プロトタイプ 148:50）の見た目を、今の作り方（PowerShell 5.1 + WPF、追加のインストール無し）でどこまで再現できるかを確かめる PoC。段 1 は「共通（トークン・フォント・部品・見る道具・比べる道具）＋起動画面＋検索画面」を対象にする。

このフォルダは本体（`scripts/`・`tests/`・`docs/`・`tools/`）から独立しており、`scripts/` のファイルを読み込まない。本体に戻すかどうかは、この PoC を見てから別に決める。マージしない前提で、作業ツリーの中だけに置く。

## 動かし方

```
powershell -ExecutionPolicy Bypass -File poc\wpf-figma\show.ps1
powershell -ExecutionPolicy Bypass -File poc\wpf-figma\compare.ps1
```

`show.ps1` はフレームを選んで原寸表示する道具、`compare.ps1` は 26 枚すべてを `reference/*.png` と比べ、`out/<フレーム名>.diff.png` と差分率の表を出す道具。

## 状態（2026-10-01）

## 再現できなかったところ

- **テキスト・アイコンのアンチエイリアシング**: Figma のラスタライザと WPF の文字描画エンジン（ClearType/DirectWrite）は、同じフォント・同じ大きさでも 1 ピクセル単位ではにじみ方が異なる。`正規表現の吹き出し`（部品）は背景色を参照画像に合わせたあとも差分率が 48.29% のままで、`diff.png` で見ると文字の輪郭だけが赤くなっており、色・レイアウトのずれではないことを確認した。文字が多いフレームほど差分率が高く出るのは、ほぼこれが理由。
- **影のぼかしの広がり方**: Figma のぼかしの値をそのまま `DropShadowEffect` の `BlurRadius` に当てているが、計算の仕方が Figma と違うため、広がり方は厳密には一致しない（`theme.xaml` にも記載）。
- **アイコンの形**: Figma のベクターを手で近似した簡易パスを使っている。SVG そのものを書き出していないため、厳密な一致は確かめていない。
- **H-R フレームの内容**: 参照画像 `reference/H-R.png` は `H` とかなり構図が違う（追加の結果グループ「議事録メモ.md」とその行、正規表現のチェック済み状態、別のバッジ文言、件数の違いなど）。`xaml/search.xaml` の検索結果一覧は静的な XAML で複数フレームが共有しており、内容を直すと他フレームのレイアウトに影響するリスクがあるため、今回は直さず再現できなかった扱いにした。
- **H 系フレームの個別の内容確認**: `H-B`・`H-P`・`E13`・`H-範囲`・`H-範囲2`・`H-row3`・`H-row4`・`H-saved` などは計画の設計の記述から dummy の状態を作ったもので、各参照画像との内容の細部（件数・ファイル名・行の内容など）までは 1 枚ずつ突き合わせていない。`H-T1`・`H-B` は「開く」のドロップダウンが開いていないことだけ個別に確認した。
- **`compare.ps1` の最終的な再実行**: 上の「比べた結果」のとおり、最後の 2 件の修正（H のドロップダウン、高速検索の表示の外枠カード）後は `show.ps1` での目視確認にとどめ、`compare.ps1` の全 26 枚の再実行はしていない（この PoC では実機の目視確認を優先する判断のため）。
